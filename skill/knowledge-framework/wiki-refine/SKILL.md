# 投资知识提炼

## 前置

提炼前先读 **仪表盘/待处理队列.md**，Dataview 查询 `FROM "原始资源仓库" WHERE status = "待提炼"` 直接获取待提炼文件列表，**不要逐个扫目录读 frontmatter**。

## 输入（全部必填）

{source_path, target_dir, category, content_type, time_sensitivity, template_path}

## 流程

1. 读 source_path 全文
2. 读 {template_path}，获取输出章节结构
3. **知识萃取分析**（填充模板前必做，见下方详细步骤）
4. 判断目标：更新已有条目 or 创建新条目（可能多条）
5. 按 {template_path} 指定的结构填充内容
6. 自动验证标记：识别方向性断言 → 写入 validations
7. 交叉链接：关联条目与被关联条目双向 wikilink
8. 清理原始资源的 _ 前缀字段
9. 保存到 {target_dir}/{category}/{标题}.md，更新源 status=已提炼

### 知识萃取分析（步骤3详细）

填充模板前，必须先完成以下分析：

1. **区分「可复用知识」与「时间绑定信息」**
   - 可复用知识：交易方法论、分析框架、判断逻辑、策略原则、认知模型
   - 时间绑定信息：具体日期、当日涨跌、账户盈亏、特定标的短期表现
2. **判断产出数量**
   - 一篇素材可能产出 ≥1 条维基条目
   - 当素材包含多个独立知识点时，拆分为多条条目
   - 每条条目围绕一个核心概念，独立成篇
   - 拆分后每条仍需走完整流程（含交叉链接）
3. **确定条目标题**——遵循标题命名规则

### 标题命名规则

- 以知识概念命名：「左侧交易者的多方向分散配置策略」
- 不以事件/日期命名：~~「6月24日上午盘面复盘」~~
- 不以原文标题作为维基条目标题
- 原文标题保留在 sources 和原始资源 frontmatter 中

## 七条提炼原则

1. 忠于原文但可泛化——论点必须来自原文，但允许从具体案例提炼为一般性论点；具体案例作为佐证保留在论据中；论点本身不应依赖特定日期或事件才能成立
2. 结构化输出——使用模板格式
3. 来源可溯——每个观点标注来源
4. 增量更新——已有条目追加不覆盖
5. 多维度提炼——一篇素材产出多条维基条目，每条围绕一个核心概念
6. 交叉链接——关联条目双向互链
7. 去时间绑定——提炼后的论点和分析框架应独立于原始素材的具体日期和事件

## 自检

- [ ] 知识萃取分析是否在填充模板前完成？
- [ ] 条目标题是否以知识概念命名（非原文标题/日期/事件）？
- [ ] 素材中的多个独立知识点是否已拆分为多条条目？
- [ ] 论点是否可独立于特定日期/事件成立？
- [ ] frontmatter category/content_type/time_sensitivity 齐全？
- [ ] 文件位置与 category 对应？
- [ ] 关联条目双向互链？
- [ ] _ 前缀字段已清除？
- [ ] validations 字段存在（如有方向性断言）？
