# 维基审查

## 输入（全部必填）

{target_dir, dimensions, output_dir, template_path}

## 流程

1. 读 {template_path}，获取报告格式
2. **读 BLOGGER_CONSOLE**（仪表盘/博主控制台.md），获取全部博主注册信息
3. 扫描 target_dir 全部条目
4. 按 dimensions 逐项检查（含博主一致性对比）
5. 按 {template_path} 生成报告
6. 保存到 {output_dir}/YYYY年M月D日-审查.md
7. **提取修复建议，用序号标注，询问用户需要修复哪些**（不可跳过）

## 七维度速查

| 维度 | 检查内容 | 阈值 |
|:---|:---|:---|
| 矛盾检测 | 同板块/个股条目间矛盾观点 | 人工判断 |
| 时效检查 | time_sensitivity 对应周期 | 短期>30天/中期>90天/长期>180天 |
| 验证回溯 | validations 历史断言状态 | 存在待验证断言 |
| 孤立检测 | 无 backlinks 或从未被查询 | backlinks=0 或 queried=0 |
| 质量检查 | 缺必填字段/文件过小/分类不匹配 | 文件<200bytes |
| 时间绑定 | 标题/内容含具体日期或事件描述 | 见下方详表 |
| 博主一致性 | 控制台与画像是否一致 | 见下方详表 |

## 时间绑定检查细则

扫描每个条目的 title 和核心观点，检测以下模式：

| 检查项 | 匹配模式 | 说明 |
|:---|:---|:---|
| 标题含具体日期 | `\d+月\d+日`、`\d{4}年`、`\d+月` | 标题不可含具体日期 |
| 标题含事件描述 | 复盘、盘面、今日、本周、早盘、收盘 | 标题应为知识概念，非事件描述 |
| 标题含时间锚定 | 「…下的」「…时的」「…后的」+ 事件 | 标题不可锚定特定事件 |
| 核心观点首句为事件叙述 | 首句描述特定日期/事件而非知识概念 | 核心观点应先陈述可复用论点，再用案例佐证 |

判定标准：
- 🔴 标题命中以上任一模式 → 必须重命名为知识概念
- 🟡 核心观点首句为事件叙述 → 建议重构为「论点先行 + 案例佐证」
- ℹ️ 事件背景/关键数据中出现日期 → 正常，不需要修改

## 博主一致性检查细则

读 BLOGGER_CONSOLE → 提取全部博主及三列状态（雪球博主/雪球关注/特别关注）→ 逐一对比画像 frontmatter 对应字段：

| 检查项 | 控制台字段 | 画像 frontmatter | 说明 |
|:---|:---|:---|:---|
| 画像是否存在 | 表中有记录 | 文件存在 | 有控制台记录但无画像文件 = 新增未提炼 |
| 画像是否多余 | 表中无记录 | 文件存在 | 无控制台记录但有画像文件 = 已删除但画像残留 |
| 别名是否一致 | 别名列有值 | `aliases` 字段为空或不完整 | 控制台别名未写入画像 frontmatter |
| 是否雪球博主 | 是否雪球博主=是/否 | — | 控制台记录为准，画像如缺失 `xq_id` 则需补 |
| 是否雪球关注 | 是否雪球关注=是 | `following: true` | 不一致则画像需修正 |
| 是否特别关注 | 是否特别关注=是 | — | 控制台记录为准，用于查询优先级 |

> 控制台默认值：空单元格 = 雪球博主「是」、雪球关注「是」、特别关注「否」

报告格式：
```
## 博主一致性

### 画像缺失（控制台有记录但无画像文件）
| 博主 | 控制台状态 | 原始资源文章数 |
|:---|:---|:---|

### 画像多余（无控制台记录但有画像文件）
| 画像文件 | 路径 |

### following 不一致
| 博主 | 控制台 | 画像 |
|:---|:---|:---|

### aliases 不一致
| 博主 | 控制台别名 | 画像 aliases |
|:---|:---|:---|
```

## 审查频率

| 类型 | 频率 |
|:---|:---|
| 全量审查 | 每周 |
| 增量审查 | 每次提炼后 |

## 修复建议与交互

报告生成后，必须：

1. 从报告中提取所有可修复的问题，按严重度排序（🔴 > 🟡 > ℹ️）
2. 用带序号的精简列表呈现修复建议，每条注明严重度、涉及条目数、预估工作量
3. **主动询问用户**：「需要修复其中哪几点？回复序号即可。」
4. 等待用户确认后再执行修复

格式示例：
```
## 修复建议

1. 🔴 补充 19 个旧条目 content_type + time_sensitivity（批量操作）
2. 🔴 删除空文件美股.md
3. 🟡 修复 2 处 wikilink 断裂
4. 🟡 统一 validations direction 不一致

需要修复哪几点？回复序号即可。
```

## 自检

- [ ] 报告覆盖所有传入的 dimensions？
- [ ] 每个问题条目标注了具体文件路径？
- [ ] 报告中无遗漏的条目？
- [ ] 是否已提取修复建议并询问用户？
