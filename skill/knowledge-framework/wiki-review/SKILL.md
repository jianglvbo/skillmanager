# 维基审查

## 输入（全部必填）

{target_dir, dimensions, output_dir, template_path}

## 流程

1. 读 {template_path}，获取报告格式
2. 扫描 target_dir 全部条目
3. 按 dimensions 逐项检查
4. 按 {template_path} 生成报告
5. 保存到 {output_dir}/YYYY年M月D日-审查.md
6. **提取修复建议，用序号标注，询问用户需要修复哪些**（不可跳过）

## 五维度速查

| 维度 | 检查内容 | 阈值 |
|:---|:---|:---|
| 矛盾检测 | 同板块/个股条目间矛盾观点 | 人工判断 |
| 时效检查 | time_sensitivity 对应周期 | 短期>30天/中期>90天/长期>180天 |
| 验证回溯 | validations 历史断言状态 | 存在待验证断言 |
| 孤立检测 | 无 backlinks 或从未被查询 | backlinks=0 或 queried=0 |
| 质量检查 | 缺必填字段/文件过小/分类不匹配 | 文件<200bytes |

## 审查频率

| 类型 | 频率 |
|:---|:---|
| 全量审查 | 每周 |
| 增量审查 | 每次提炼后 |

## 修复建议与交互

报告生成后，必须：

1. 从报告中提取所有可修复的问题，按严重度排序（🔴 > 🟡 > ℹ️）
2. 用带序号的精简列表呈现修复建议，每条注明严重度、涉及条目数、预估工作量
3. **主动询问用户**：「需要修复其中哪几点？回复序号即可。」
4. 等待用户确认后再执行修复

格式示例：
```
## 修复建议

1. 🔴 补充 19 个旧条目 content_type + time_sensitivity（批量操作）
2. 🔴 删除空文件美股.md
3. 🟡 修复 2 处 wikilink 断裂
4. 🟡 统一 validations direction 不一致

需要修复哪几点？回复序号即可。
```

## 自检

- [ ] 报告覆盖所有传入的 dimensions？
- [ ] 每个问题条目标注了具体文件路径？
- [ ] 报告中无遗漏的条目？
- [ ] 是否已提取修复建议并询问用户？
