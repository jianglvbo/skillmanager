# 博主分析框架 · 操作手册

本 skill 是博主分析框架的**操作手册**，定义所有操作步骤和规则。博主画像数据存储在 Obsidian vault（`我的知识库/博主分析框架/博主画像/`）中。

> 本 skill 专注于博主画像的加工与沉淀。投资知识相关操作不在本 skill 职责范围内。

## 系统架构

```
粗制品/ →(粗加工)→ 博主分析框架/原始资源仓库/ →(提炼)→ 博主分析框架/博主画像/
                                                                    ↓
                                                          问答看板/ ←(问答)
                                                                    ↓
                                                          博主分析框架/博主画像/ ←(回流)
```

### 目录结构

```
我的知识库/                           ← vault root
├── 粗制品/                          ← 共享暂存区
├── 问答看板/                        ← 共享产出
├── 仪表盘/
│   ├── 博主控制台.md                ← 博主主注册表（手动维护，权威来源）
│   └── 博主全景.md                  ← 博主总览索引（Dataview 只读）
└── 博主分析框架/                    ← 本 skill 的领域
    ├── 原始资源仓库/                ← 博主相关素材
    └── 博主画像/                    ← 每位博主一份 .md
```

> `仪表盘/博主控制台.md` 是博主画像的**唯一权威来源**。添加/删除博主、修改标记字段均在此操作。每次提炼画像时必须先读控制台，完成后更新对应行。

---

## 核心约定

1. **日期格式**：`YYYY年M月D日`（如 `2026年6月22日`）
2. **文件命名**：`{博主名}.md`，存放于 `博主分析框架/博主画像/`
3. **wikilink 路径**：使用完整路径，不加 emoji 前缀
4. **博主画像只存人类可读内容**：筛选、提炼、归档后的知识产物
5. **增量更新**：已有画像追加而非覆盖，保留历史演变痕迹

## 流程一：粗加工

**流向**：`粗制品/` → `博主分析框架/原始资源仓库/`

### 步骤

1. **筛选**：粗制品 frontmatter 中 `_route` 为 `博主分析` 或 `both` 的文件
2. **补全 frontmatter**：按原始资源模板填写
3. **保留原文**：不精简、不删节
4. **移动**：移到 `博主分析框架/原始资源仓库/`
5. **删除粗制品原件**

### 原始资源模板

```yaml
---
title: 文章标题
source: 来源链接
author: 作者名
date: YYYY年M月D日
recorded: YYYY年M月D日
type: 帖子 | 长文
blogger: 关联博主名
status: 待提炼 | 已提炼 | 无需提炼
---
```

## 流程二：提炼

**流向**：`博主分析框架/原始资源仓库/` → `博主分析框架/博主画像/`

### 步骤

1. **读控制台**：先读取 `仪表盘/博主控制台.md`，确认目标博主是否在注册表中
   - 如果博主不在控制台 → 先在控制台添加一行，再创建画像
   - 根据控制台字段解读博主标记（是否雪球博主、别名、特别关注、雪球关注）
2. **选择资源**：筛选 `status: 待提炼` 的原始资源
3. **判断目标**：更新已有画像 vs 创建新画像
4. **撰写画像**：按「博主画像模板」创建或追加
5. **更新状态**：原始资源 `status: 已提炼`
6. **更新控制台**：提炼完成后，检查并同步控制台对应行的字段变化
   - 如果新增了别名但控制台未记录 → 补入别名列（逗号分隔）
   - 如果首次获取到雪球 ID → 标记「是否雪球博主」为「是」

### 博主控制台字段

| 字段 | 说明 | 默认值 |
|------|------|:---:|
| 博主 | 博主名，与画像文件名一致 | — |
| 别名 | 曾用名/昵称，多个用逗号分隔 | 空 |
| 是否雪球博主 | 是否在雪球平台有账号 | 是 |
| 是否雪球关注 | 是否在雪球上关注了此人 | 是 |
| 是否特别关注 | 个人优先级标记 | 否 |

> 空单元格 = 默认值。AI 读表时按默认值解读。

### 提炼原则

1. **忠于原文**：不添加原文没有的观点
2. **结构化输出**：使用模板格式
3. **来源可溯**：每个观点标注来源
4. **增量更新**：追加而非覆盖
5. **多维度覆盖**：一篇资源可能补充画像的多个维度（投资风格、核心观点、持仓变动等）

### 博主画像模板

#### Frontmatter

```yaml
---
blogger: 博主名
xueqiu_id: 雪球数字ID
groups: [分组标签]
markets: [关注市场]
style_keywords: [投资风格关键词]
followers: 粉丝数
avatar: 一句话定位
post_count: 已分析帖子数
createDate: YYYY年M月D日
updateDate: YYYY年M月D日
sources: [原始资源链接]
---
```

#### 正文结构

```markdown
## 一句话定位
（该博主最核心的投资标签）

## 投资风格
（风格特征、偏好市场、操作习惯）

## 核心观点
（代表性投资观点，按主题分组）
  - 主题A：观点 + 来源时间
  - 主题B：观点 + 来源时间

## 关注标的
（常提的股票/板块及态度）

## 经典语录
（有代表性的原文引用）

## 演变轨迹
（观点变化的时间线记录，增量追加）

## 关联条目
（相关博主、板块、个股的 wikilink）
```

## 流程三：问答

**流向**：`博主分析框架/博主画像/` → `问答看板/`

### 步骤

1. **定义问题**：明确想了解什么（某博主观点 / 博主对比 / 谁关注某话题）
2. **查询画像**：读取对应博主画像文件
3. **结构化输出**：输出到 `问答看板/历史问答/`
4. **命名规范**：`YYYY年M月D日-主题.md`

### 常见查询模式

| 查询类型 | 方法 |
|----------|------|
| 某博主怎么看某话题 | 读该博主画像 + 搜索相关观点 |
| 博主风格对比 | 读两篇画像 + 对比风格、观点差异 |
| 谁关注某板块 | 遍历画像 frontmatter 的 markets + 搜索正文 |
| 博主全景 | 读 `仪表盘/博主控制台.md`（主注册表）或 `仪表盘/博主全景.md`（Dataview） |
| 特别关注列表 | 读 `仪表盘/博主控制台.md`，筛选「是否特别关注=是」的行 |

## 流程四：回流

**流向**：`问答看板/` → `博主分析框架/博主画像/`

### 步骤

1. 问答中产生新洞察 → 追加到对应博主画像
2. 在画像的「演变轨迹」中记录更新
3. 标记问答文件 `reflow: true`

### 原则

- **人工判断**：回流前需确认
- **不覆盖**：追加方式更新
- **可追溯**：每次回流留痕

---

## 博主画像审查

### 审查维度

1. **完整性**：是否覆盖了多个时间段的观点
2. **时效性**：最近更新是否超过 90 天
3. **连接度**：backlinks 是否为空（孤立画像）
4. **一致性**：画像内观点是否有自我矛盾

### 审查频率

| 类型 | 频率 |
|------|------|
| 全量审查 | 每月 |
| 增量审查 | 每次提炼后 |

---

## 注意事项

1. **画像只存知识产物**：博主原始帖子不持久化，仅保留提炼后的画像
2. **控制台是权威来源**：`仪表盘/博主控制台.md` 是博主的唯一注册表。提炼前必读，提炼后必更新
3. **命名统一**：博主画像文件名用博主名，不加编号前缀
4. **双向链接**：关联的博主、板块、个股必须用 wikilink 互链
