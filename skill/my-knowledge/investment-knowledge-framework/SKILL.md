# 投资知识分析框架

本 skill 是投资知识分析框架的**操作手册**，定义所有操作步骤和规则。本 skill 不负责调度/触发策略——何时执行、如何触发由用户或外部编排层决定。

> **博主画像**已拆分至独立的「博主分析框架」，不属于本 skill 的职责范围。

## 系统架构

三层单向流水线（本 skill 负责的段落）：

```
粗制品/ →(粗加工)→ 投资分析框架/原始资源仓库 →(提炼)→ 投资分析框架/维基仓库
                                                                        ↓
                                                              问答看板/ ←(问答)
                                                                        ↓
                                                              投资分析框架/维基仓库 ←(回流)
```

## 核心约定

1. **日期格式**：`YYYY年M月D日`（如 `2026年6月18日`），不用 YYYY-MM-DD
2. **文件命名**：原始资源文件名不带日期前缀（日期通过 frontmatter `date` 字段记录）
3. **wikilink 路径**：使用完整路径，路径中不加 emoji 前缀（不用 `🌍 宏观`，直接用 `宏观`）
4. **多条目创建**：一篇文章必须从多维度提炼（概念 + 个股/板块 + 宏观等），不要只创建一个条目
5. **交叉链接**：每个维基条目的「关联条目」section 必须列出相关条目，且目标条目也要反向链接
6. **用户反馈即规则更新**：当用户提出改进建议时，不仅修正当前输出，还要同步更新框架规则和变更日志

## 处理指令传播

上游流程在粗制品 frontmatter 中以 `_` 前缀字段写入处理指令，这些字段沿流水线传播：

| 字段 | 含义 | 示例 |
|------|------|------|
| `_route` | 路由目标（博主名/来源标识） | `_route: 段永平` |
| `_profile` | 博主画像关联标记 | `_profile: true` |
| `_alias` | 博主别名 | `_alias: 大道无形我有形` |
| `_xueqiu` | 雪球 ID | `_xueqiu: 1247347556` |

**传播规则**：
1. **粗加工**阶段：将 `_` 前缀字段从粗制品原样复制到原始资源 frontmatter
2. **提炼**阶段：读取 `_` 前缀字段辅助判断来源和关联，提炼完成后从原始资源 frontmatter 中**删除**所有 `_` 前缀字段
3. 维基条目中**不保留** `_` 前缀字段——相关信息已融入 `sources`、`tags` 等正式字段

## 流程一：粗加工

**流向**：`粗制品/` → `投资分析框架/原始资源仓库/`

### 步骤

1. **读取**：通过合适方式获取内容
   - 微信文章：用 `python3 -c` + requests + 微信 UA（`MicroMessenger/8.0.49`）从 `#js_content` 提取正文
   - 雪球文章：通过雪球 API 或网页抓取
   - 抖音视频：通过 web API `/aweme/v1/web/aweme/detail/`
   - 用户直接提供：直接使用
2. **判断类型**：帖子 / 长文 / 链接 / 问答
   - 微信公众号 → `长文`
   - 抖音转录 → `帖子`（即使文本较长）
   - 雪球短帖 → `帖子`
   - 雪球长文 → `长文`
3. **补全 frontmatter**：按「原始资源模板」填写所有字段，保留 `_` 前缀字段
4. **保留原文**：不精简、不删节，逐字稿去掉时间轴格式整理为连贯段落
5. **清理**：删除尾部反馈链接（如"内容效果不满意？点此反馈"）
6. **保留图片**：保留 `![[附件/图片/xxx.jpg]]` 引用
7. **移动**：从 `粗制品/` 移到 `投资分析框架/原始资源仓库/{类型}/`
8. **删除粗制品原件**：移动后从 `粗制品/` 中删除

### 原始资源模板

```yaml
---
title: 文章标题
source: 来源链接
author: 作者名
date: YYYY年M月D日
recorded: YYYY年M月D日
type: 帖子 | 长文 | 链接 | 问答
status: 待提炼 | 已提炼 | 无需提炼
wiki_ref: ""
tags: []
# _ 前缀字段（如有，从粗制品继承）
_route: ""
_profile: false
---
```

**标签速查**：
- 板块：`板块/算力`、`板块/新能源`、`板块/消费`、`板块/医药`、`板块/半导体`、`板块/金融`、`板块/地产`、`板块/互联网`、`板块/风电` 等
- 市场：`市场/A股`、`市场/港股`、`市场/美股`、`市场/欧洲`
- 类型：`类型/概念`、`类型/投资理念`、`类型/个股`、`类型/板块`、`类型/宏观`
- 状态：`状态/待提炼`、`状态/已提炼`、`状态/无需提炼`

**存放目录**：

| 目录 | type |
|------|------|
| `投资分析框架/原始资源仓库/帖子/` | 帖子 |
| `投资分析框架/原始资源仓库/长文/` | 长文 |
| `投资分析框架/原始资源仓库/链接/` | 链接 |
| `投资分析框架/原始资源仓库/问答/` | 问答 |

## 流程二：提炼

**流向**：`投资分析框架/原始资源仓库/` → `投资分析框架/维基仓库/`

### 步骤

1. **选择资源**：查看待提炼列表（按 `type ASC, date DESC` 排序）
2. **识别类型**：帖子 / 长文 / 链接 / 问答
3. **判断目标**：更新现有条目 vs 创建新条目
4. **撰写维基条目**：按「维基条目模板」创建，遵循提炼原则
5. **自动验证标记**：识别方向性断言，写入 `validations` 字段（见「自动验证机制」）
6. **清理处理指令**：从原始资源 frontmatter 中删除所有 `_` 前缀字段
7. **更新状态**：原始资源 `status: 已提炼`，添加 `wiki_ref` 指向产出条目
8. **更新变更日志**

### 提炼六原则

1. **忠于原文**：不添加原文没有的观点
2. **结构化输出**：使用模板格式
3. **来源可溯**：每个观点标注来源
4. **增量更新**：更新已有条目时追加而非覆盖
5. **多维度提炼**（重要）：一篇资源可能产出多个维基条目：
   - **概念/投资理念**：核心理论、方法论
   - **个股**：涉及的具体股票分析
   - **板块**：涉及的具体行业/板块分析
   - **宏观**：宏观趋势、周期判断
6. **交叉链接**：在「关联条目」section 中用 wikilink 互相引用相关条目

### 三维正交分类

每个维基条目使用三个正交维度进行分类：

**维度一：category（知识领域）**

| category 值 | 存放目录 |
|-------------|----------|
| 投资理念 | `投资分析框架/维基仓库/投资理念/` |
| 概念 | `投资分析框架/维基仓库/概念/` |
| 板块 | `投资分析框架/维基仓库/板块/` |
| 个股-港股 | `投资分析框架/维基仓库/个股/港股/` |
| 个股-A股 | `投资分析框架/维基仓库/个股/A股/` |
| 个股-美股 | `投资分析框架/维基仓库/个股/美股/` |
| 宏观 | `投资分析框架/维基仓库/宏观/` |

**维度二：content_type（内容类型）**

| content_type | 说明 | 典型场景 |
|-------------|------|----------|
| 方法论 | 投资方法、分析框架、操作策略 | "如何判断底部区间" |
| 案例分析 | 具体事件的复盘与分析 | "2025年港股科技股反弹复盘" |
| 数据解读 | 财报、经济数据、指标分析 | "5月社融数据解读" |
| 观点评论 | 市场观点、策略评论、争论分析 | "当前是否应该加仓半导体" |
| 市场综述 | 市场全局回顾与展望 | "2026年上半年A股市场综述" |

**维度三：time_sensitivity（时效性）**

| time_sensitivity | 说明 | 审查周期 |
|-----------------|------|----------|
| 长期有效 | 基础理论、方法论、历史规律 | 180 天 |
| 中期有效 | 行业趋势、中期判断、季度分析 | 90 天 |
| 短期有效 | 市场热点、短期策略、事件驱动 | 30 天 |
| 已过期 | 判断已被证伪或条件已根本改变 | 归档不删 |

> 分类正交性意味着任何组合都合法：例如 `category: 板块` + `content_type: 数据解读` + `time_sensitivity: 短期有效` 表示一篇板块数据的短期解读。

### 维基条目模板

#### Frontmatter（核心固定字段）

```yaml
---
title: 条目标题
category: 投资理念 | 概念 | 板块 | 个股-港股 | 个股-A股 | 个股-美股 | 宏观
content_type: 方法论 | 案例分析 | 数据解读 | 观点评论 | 市场综述
time_sensitivity: 长期有效 | 中期有效 | 短期有效 | 已过期
summary: 核心观点一句话概括
tags: []
createDate: YYYY年M月D日
updateDate: YYYY年M月D日
sources: []
queried: 0
last_queried: null
---
```

#### 正文结构（固定 + 类型特定 + 自由扩展）

```markdown
## 核心观点
（固定模块 — 简要概述，所有类型共用）

## 详细分析
（类型特定模块 — 按 content_type 选择子模板，见下方）

## 关键数据
（固定模块 — 重要数据点，所有类型共用）

## 关联条目
（固定模块 — 相关维基条目 wikilink，确保双向链接）

## 来源
（固定模块 — 关联的原始资源链接）
```

#### 详细分析子模板（按 content_type 选择）

**方法论**：
```markdown
## 详细分析

### 核心逻辑
（方法论的基本原理和推理链）

### 适用场景
（什么条件下适用，什么条件下不适用）

### 局限性
（已知的局限、盲区、前提假设）
```

**案例分析**：
```markdown
## 详细分析

### 事件背景
（时间、市场环境、触发因素）

### 分析过程
（分析的逻辑链、关键判断节点）

### 结论与启示
（可复用的经验教训）
```

**数据解读**：
```markdown
## 详细分析

### 数据概览
（核心数据点、同比/环比变化）

### 趋势分析
（数据背后的趋势、拐点信号）

### 投资含义
（对投资决策的具体影响）
```

**观点评论**：
```markdown
## 详细分析

### 核心论点
（主要观点和立场）

### 论据
（支撑论点的数据、逻辑、案例）

### 反向观点
（对立观点及其合理性）
```

**市场综述**：
```markdown
## 详细分析

### 市场概览
（指数表现、成交量、资金流向）

### 驱动因素
（政策、基本面、情绪面分析）

### 展望
（后续关注点、潜在风险与机会）
```

> 以上子模板为推荐结构，实际撰写时可根据内容自由扩展，添加额外 section。

### 自动验证机制

提炼过程中，AI 应自动识别原文中的**方向性断言**（对市场/个股/板块的涨跌判断），并在维基条目 frontmatter 中标记：

```yaml
validations:
  - claim: "恒生科技已到底部区间"
    direction: 看涨
    metric: 恒生科技指数
    date: YYYY年M月D日
    source: 某博主
  - claim: "美联储年内将降息三次"
    direction: 看涨
    metric: 联邦基金利率
    date: YYYY年M月D日
    source: 某分析师
```

**字段说明**：
- `claim`：原文中的断言原文（精简但不改变含义）
- `direction`：看涨 / 看跌 / 中性
- `metric`：可用于验证的客观指标名称
- `date`：断言发表的日期
- `source`：断言来源（作者名）

**验证机制用途**：
- 审查时可回溯验证历史断言的准确性
- 为后续「观点评论」类条目提供正反论据
- 帮助识别高准确率的信息来源

## 流程三：问答

**流向**：`投资分析框架/维基仓库/` → `问答看板/`

### 步骤

1. **定义问题**：明确分析维度
2. **查询维基**：按类型查找相关条目
3. **结构化输出**：按「问答看板模板」输出到 `问答看板/历史问答/`
4. **更新追踪**：更新引用条目的 `queried` 计数和 `last_queried` 日期

### 查询路径

| 分析类型 | 查询路径 |
|----------|----------|
| 板块分析 | `投资分析框架/维基仓库/板块/` + `投资分析框架/维基仓库/个股/<市场>/` |
| 个股分析 | `投资分析框架/维基仓库/个股/<市场>/<股票名>.md` + 对应板块 |
| 宏观分析 | `投资分析框架/维基仓库/宏观/` + `投资分析框架/维基仓库/概念/` |
| 方法论查询 | `投资分析框架/维基仓库/投资理念/`（按 content_type 筛选） |
| 跨维度查询 | 通过 tags 和 validations 字段进行交叉检索 |

### 问答看板模板

```yaml
---
title: 问答主题
date: YYYY年M月D日
wiki_sources: []
quality: 优质 | 一般 | 待评估
reflow: false
---
```

命名规范：`YYYY年M月D日-主题.md`，存放于 `问答看板/历史问答/`

### 查询原则

1. **先全貌后详情**：先用 Obsidian MCP 列出目录或用 Dataview 查询获取全貌，再深入具体条目
2. **多维度交叉**：从概念、板块、个股、宏观等多角度获取信息，利用三维分类进行精细筛选
3. **来源可溯**：查询结果必须标注引用的维基条目
4. **关注时效性**：优先引用最近更新的内容，注意 `time_sensitivity` 维度

## 流程四：迭代/回流

**流向**：`问答看板/` → `投资分析框架/维基仓库/` 或 `粗制品/`

### 步骤

1. **筛选候选**：找出 `quality: 优质` 且 `reflow: false` 的问答
2. **判断类型**：
   - **更新**：问答中有新洞察补充到已有维基条目
   - **新建**：问答中产生了全新的分析维度
   - **归档**：问答内容已过时，无回流价值
3. **执行回流**：更新维基条目或将内容放入 `粗制品/` 重新走流程
4. **记录**：在 `问答看板/回流记录.md` 中记录回流详情
5. **标记**：更新问答文件的 `reflow: true`

### 原则

- **人工判断**：回流需要人工确认，不自动执行
- **不覆盖**：以追加方式更新维基条目，不覆盖原有内容
- **可追溯**：每次回流都在回流记录和变更日志中留痕

## 审查规则

### 审查维度

1. **矛盾检测**：扫描同板块/个股条目间的矛盾观点
2. **时效性检查**：
   - 根据 `time_sensitivity` 判断：长期有效条目 > 180 天未更新 → 可能过时；中期有效 > 90 天 → 可能过时；短期有效 > 30 天 → 可能过时
   - `time_sensitivity: 已过期` → 审查是否需要归档
   - 引用季度数据且季度已过 → 数据过期
   - 来源 `date` > 180 天 → 来源时效低
3. **验证回溯**：检查 `validations` 中的历史断言，标记已验证/已证伪/待验证
4. **孤立文件检测**：backlinks 为空 → 孤立条目；`queried: 0` 且 `updateDate` > 60 天 → 长期滞销
5. **质量检查**：缺少必填字段、文件 < 200 bytes、category 与目录不匹配、content_type 与正文结构不匹配

### 审查频率

| 类型 | 频率 |
|------|------|
| 全量审查 | 每周 |
| 增量审查 | 每次提炼后 |

## 查询配方

> 以下 Dataview 查询供 AI 在执行操作时直接使用。通过 Obsidian MCP 的 vault_read（targetType: heading/block）或 search_query 执行。

### 待提炼队列

```dataview
TABLE date, type, author, file.folder
FROM "投资分析框架/原始资源仓库"
WHERE status = "待提炼"
SORT type ASC, date DESC
```

### 维基全量视图

```dataview
TABLE category, content_type, time_sensitivity, summary, queried, updateDate
FROM "投资分析框架/维基仓库"
WHERE category
SORT category ASC, updateDate DESC
```

### 按内容类型筛选

```dataview
TABLE category, time_sensitivity, summary, updateDate
FROM "投资分析框架/维基仓库"
WHERE content_type = "方法论"
SORT updateDate DESC
```

### 时效性过期预警

```dataview
TABLE category, content_type, time_sensitivity, summary, updateDate
FROM "投资分析框架/维基仓库"
WHERE (time_sensitivity = "短期有效" AND date(today) - updateDate > dur(30 days))
   OR (time_sensitivity = "中期有效" AND date(today) - updateDate > dur(90 days))
   OR (time_sensitivity = "长期有效" AND date(today) - updateDate > dur(180 days))
SORT time_sensitivity ASC, updateDate ASC
```

### 待验证断言

```dataview
TABLE category, summary, validations
FROM "投资分析框架/维基仓库"
WHERE validations
SORT updateDate DESC
```

### 知识孤岛（连接度 = 0）

```dataview
TABLE category, content_type, summary, updateDate, (length(file.inlinks) + length(file.outlinks)) AS 连接度
FROM "投资分析框架/维基仓库"
WHERE (length(file.inlinks) + length(file.outlinks)) = 0
SORT updateDate DESC
```

### 滞销条目（queried = 0）

```dataview
TABLE category, content_type, summary, queried, updateDate
FROM "投资分析框架/维基仓库"
WHERE queried = 0
SORT updateDate ASC
```

### 健康度指标

| 指标 | 含义 | 阈值 |
|------|------|------|
| 连接度 | `inlinks + outlinks`，条目在知识网络中的枢纽程度 | = 0 → 知识孤岛 |
| queried | 被问答引用的次数 | = 0 → 未被利用 |
| status | 原始资源的提炼进度 | = 待提炼 → 未加工 |
| time_sensitivity | 条目时效性 | 超过对应周期 → 需审查 |
| validations | 待验证断言数量 | 存在未验证断言 → 可回溯验证 |

## 注意事项

1. **wikilink 路径中不加 emoji**：用 `[[投资分析框架/维基仓库/宏观/恒生科技底部判断]]` 而不是 `[[投资分析框架/维基仓库/🌍 宏观/恒生科技底部判断]]`
2. **双向链接**：A 的关联条目链接 B 时，B 的关联条目也要链接 A
3. **非投资内容**：仍归档到原始资源仓库，但 `status: 无需提炼`，不进入提炼队列
4. **vault 只存数据**：vault 内只放原始资源、维基条目、问答产物和仪表盘。流程规则、模板、标签等 AI 操作手册全部在 skill 中
5. **变更日志只记内容流转**：记录什么资源被录入、提炼出了什么维基条目，以及重大审查事件。框架自身的调整不记入变更日志
6. **博主画像不在本框架内**：博主画像相关操作由博主分析框架处理，本框架的维基仓库中不包含博主画像目录
7. **共享资源路径**：`待处理链接.md`、`粗制品/`、`问答看板/` 位于 vault 根目录（`我的知识库/`），不是 `投资分析框架/` 的子目录
8. **处理指令清理**：提炼完成后务必从原始资源 frontmatter 中删除所有 `_` 前缀字段
9. **三维分类完整性**：每个维基条目必须同时填写 category、content_type、time_sensitivity 三个维度
10. **仪表盘在 vault 根目录**：仪表盘文件（维基总览、待处理队列、博主全景、变更日志）统一放在 `仪表盘/` 目录（vault 根目录），不在任何子框架内
