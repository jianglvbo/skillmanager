# 链接转译与路由

本 skill 是知识框架的**共享入口步骤**，负责两件事：
1. **链接转译** — 将 URL 抓取为 markdown 粗制品
2. **路由分发** — 根据内容特征决定下游流向哪个分析框架

> 本 skill 只做「转译 + 路由」，不做粗加工、提炼或任何深度分析。下游由对应的分析框架接手。

## 目录结构

```
我的知识库/                       ← vault root (Obsidian)
├── 待处理链接.md                ← 本 skill 的输入队列
├── 粗制品/                      ← 本 skill 的输出目录
├── 仪表盘/                      ← 仪表盘（vault 根目录）
├── 投资分析框架/                ← 下游：投资知识方向

    └── 索引/
```

## 一、待处理链接.md（输入队列）

位于 vault 根目录：`我的知识库/待处理链接.md`

### 格式

```markdown
| 链接 | 是否画像 | 别名 | 是否雪球 |
|------|:--------:|------|:--------:|
| https://xueqiu.com/1234/5678 | ✓ | 唐朝 | ✓ |
| https://mp.weixin.qq.com/s/xxx | | | |
```

### 列说明

| 列名 | 填写方 | 含义 |
|:-----|:-------|:-----|
| 链接 | 用户 | 待处理的 URL |
| 是否画像 | 用户 | 填 `✓` 表示需要为该博主/作者建立画像，留空则不需要 |
| 别名 | 用户 | 博主/作者的自定义别名（用于下游文件命名） |
| 是否雪球 | 用户 | 填 `✓` 表示来源是雪球平台，留空则不是 |

## 二、链接转译（URL → Markdown）

### 抓取策略

按平台采用不同抓取方式：

| 平台 | 方法 | 工具 |
|:-----|:-----|:-----|
| 雪球 | autocli read 提取正文 | autocli |
| 公众号/网页 | WebFetch 或 curl 提取正文 | WebFetch / curl |
| 小红书 | CDP 浏览器模式（需 Chrome 远程调试） | web-access CDP |
| 抖音 | API 获取视频 URL → curl 下载 → ffmpeg 提取音频 → whisper-cli 转写 | ffmpeg + whisper-cpp |

### 抓取优先级

1. **WebFetch / autocli read** — 优先使用 Agent 自带工具
2. **CDP 浏览器** — 小红书、需要登录态的动态页面
3. **curl** — WebFetch 失败时的降级方案

**只抓取原文正文，不抓取评论和讨论。**

## 三、路由逻辑

抓取完内容后，根据内容特征判断路由方向。路由结果写入粗制品 frontmatter 的 `_route` 字段。

### 路由规则

| 条件 | `_route` 值 | 说明 |
|:-----|:------------|:-----|
| 来源是雪球博主的帖子（个人投资观点、持仓分享、市场感悟） | `博主分析` | 流向博主分析框架 |
| 来源是非博主类的分析文章（行业研究、公司分析、方法论、宏观分析） | `投资知识` | 流向投资分析框架 |
| 雪球博主的帖子，但内容涉及具体个股/板块的深度分析 | `both` | 同时流向两个框架 |

### 路由判断流程

1. **看来源**：是否雪球？是否来自已注册的博主？
2. **看内容**：
   - 个人投资感悟、持仓变动、市场点评 → `博主分析`
   - 行业深度、公司研究、投资方法论、宏观分析 → `投资知识`
   - 博主写的个股/板块深度分析（兼具个人视角和知识价值） → `both`
3. **看用户指令**：待处理链接中的「是否画像」列打 ✓ 时，倾向 `博主分析` 或 `both`

### 路由不确定时

- 默认路由为 `投资知识`
- 如果用户打了「是否画像」✓，默认路由为 `博主分析`

## 四、粗制品输出

### 输出位置

```
我的知识库/粗制品/{标题}.md
```

### 粗制品 frontmatter

每个粗制品文件的 frontmatter 包含两类字段：

**元数据字段**（内容信息）：

```yaml
title: "文章标题"
source: "雪球/微信公众号/抖音/..."
author: "作者名"
url: "原始链接"
date: "发布日期（如能获取）"
recorded: "抓取日期"
type: "帖子/长文/链接/问答"
status: "待处理"
```

**处理指令字段**（`_` 前缀，供下游读取，提炼完成后清除）：

```yaml
_route: "投资知识"       # 路由方向：投资知识 / 博主分析 / both
_profile: true           # 是否需要建立画像（来自待处理链接「是否画像」列）
_alias: "唐朝"           # 博主别名（来自待处理链接「别名」列，无则为空字符串）
_xueqiu: true            # 是否雪球来源（来自待处理链接「是否雪球」列）
```

### 完整 frontmatter 示例

```yaml
---
title: "白酒行业2024年展望"
source: "雪球"
author: "唐朝"
url: "https://xueqiu.com/1234/5678"
date: "2024-03-15"
recorded: "2024-03-16"
type: "长文"
status: "待处理"
_route: "both"
_profile: true
_alias: "唐朝"
_xueqiu: true
---
```

### 粗制品正文

- 保留原文完整内容
- 逐字稿（如抖音视频）整理为自然段落，去掉时间轴格式
- 不深入分析，不添加评论

## 五、处理指令字段说明

这些 `_` 前缀字段是整个流水线的内部通信机制：

| 字段 | 类型 | 来源 | 下游用途 |
|:-----|:-----|:-----|:---------|
| `_route` | string | 本 skill 路由判断 | 下游根据此字段决定由哪个框架处理 |
| `_profile` | boolean | 待处理链接「是否画像」列 | 博主分析框架据此决定是否创建/更新博主画像 |
| `_alias` | string | 待处理链接「别名」列 | 下游用此别名命名文件和画像 |
| `_xueqiu` | boolean | 待处理链接「是否雪球」列 | 下游据此决定是否调用雪球相关工具 |

**生命周期**：这些字段在粗制品创建时写入，在提炼完成后从最终文件中清除。

## 六、IM 渠道快捷入口

当用户通过飞书/IM 发送链接时：

1. **回复**：`收到，纳入分析`
2. **自动追加到待处理链接.md**：在表格末尾新增一行
   - 链接：用户发送的 URL
   - 是否画像/别名/是否雪球：留空（用户后续可手动补充）
3. **如果用户同时给出指令**（如"这个要画像"、"雪球博主"），则自动填写对应列

## 注意事项

- **本 skill 只做转译和路由**：不做粗加工、提炼、维基生成等下游工作
- 雪球链接优先用 `autocli read` 抓取
- 抖音视频转写只做基础分段，不去口癖、不修正 Whisper 小错误
- `_route: both` 时，粗制品只写一份到 `粗制品/`，下游两个框架各自读取并处理
- 处理指令字段（`_` 前缀）是临时的，提炼完成后必须清除
- 待处理链接.md 中的行在被处理完后，不删除（保留历史记录）
