# 投资知识提炼

## Default Stance

### 核心原则
- **纯执行引擎**：所有参数由 pipeline 传入，不硬编码路径或规则。
- **区分知识与信息**：提炼可复用知识（方法论、框架、判断逻辑），过滤时间绑定信息（当日涨跌、账户盈亏）。
- **概念命名**：条目标题以知识概念命名，不用原文标题或日期。
- **拆分优先**：一篇素材含多个独立知识点时，拆为多条条目，每条独立成篇。

### 禁止行为
- 绝不添加原文没有的信息
- 绝不跳过提炼前分析直接填充模板
- 绝不创建单向 wikilink（关联条目必须双向互链）
- 绝不硬编码路径或模板

## Workflow

**第一步**：读 {rules_path}，获取提炼规则定义（category映射、标题规则、frontmatter清单、提炼原则）
**第二步**：读 source_path 全文
**第三步**：读 {template_path}，获取输出章节结构
**第四步**：提炼前分析——区分可复用知识 vs 时间绑定信息；判断产出数量（≥1 条）；确定条目标题
**第五步**：判断目标——更新已有条目 or 创建新条目
**第六步**：按 {template_path} 指定的结构填充内容
**第七步**：自动验证标记——识别方向性断言 → 写入 validations
**第八步**：交叉链接——关联条目与被关联条目双向 wikilink
**第九步**：清理原始资源的 _ 前缀字段
**第十步**：保存到 {target_dir}/{category}/{标题}.md，更新源 status=已提炼

### 提炼前分析（第四步详细）

填充模板前，必须先完成以下分析：

1. **区分「可复用知识」与「时间绑定信息」**
   - 可复用知识：交易方法论、分析框架、判断逻辑、策略原则、认知模型
   - 时间绑定信息：具体日期、当日涨跌、账户盈亏、特定标的短期表现
2. **判断产出数量**
   - 一篇素材可能产出 ≥1 条维基条目
   - 当素材包含多个独立知识点时，拆分为多条条目
   - 每条条目围绕一个核心概念，独立成篇
   - 拆分后每条仍需走完整流程（含交叉链接）
3. **确定条目标题**——按 {rules_path} 中的标题命名规则

## 输入（全部必填）

{source_path, target_dir, category, content_type, time_sensitivity, template_path, rules_path}

## 提炼原则

从 {rules_path} 读取，当前包含 7 条原则（见规则文件）。

## Output Format

提炼产出为一个或多个维基条目文件：
- 位置：`{target_dir}/{category}/{标题}.md`
- 内容：frontmatter（三维分类 + validations + sources）+ 结构化正文
- 源资源 status 更新为「已提炼」

## Relative Files

| 场景 | 加载文件 | 内容 |
|:---|:---|:---|
| 始终 | {template_path} | 维基条目模板（由 pipeline 按 content_type 选择） |
| 始终 | {rules_path} | 提炼规则定义 |

## Source Hierarchy

| 优先级 | 来源 |
|:---|:---|
| 1 | 用户显式约定 |
| 2 | Obsidian 规范 |
| 3 | knowledge-pipeline（路径常量、模板结构、规则文件） |
| 4 | 工程实践验证 |

## 自检

- [ ] 是否已读 {rules_path} 获取提炼规则？
- [ ] 提炼前分析是否在填充模板前完成？
- [ ] 条目标题是否以知识概念命名（非原文标题/日期/事件）？
- [ ] 素材中的多个独立知识点是否已拆分为多条条目？
- [ ] 论点是否可独立于特定日期/事件成立？
- [ ] frontmatter 必填字段齐全（按 rules_path 定义）？
- [ ] validations 字段存在（无断言时为空数组 `[]`）？
- [ ] 文件位置与 category 对应（按 rules_path 映射）？
- [ ] 关联条目双向互链？
- [ ] _ 前缀字段已清除？
- [ ] 正文包含「核心观点」和「关键数据」章节（所有类型共用）？
