## frontmatter 必填字段（11 个）

title, category, content_type, time_sensitivity, summary, tags, createDate, updateDate, sources, queried, last_queried

### 非空约束

以下字段不可为空字符串：category, content_type, time_sensitivity, summary

tags 可为空数组 `[]`，但不可为空字符串 `""`。

### YAML 格式约束（防止解析错误）

- **category**：始终使用 YAML block list 格式（`category:\n  - "值1"\n  - "值2"`），即使只有一个值也用列表格式。禁止在标量值下方追加列表项
- **tags**：始终使用 YAML block list 格式（`tags:\n  - "标签1"\n  - "标签2"`）。禁止使用行内流序列 `tags: [...]` 后追加列表项
- **sources**：纯路径字符串，不加 `[[wikilink]]` 语法。如 `原始资源仓库/帖子/xxx.md`，不是 `[[原始资源仓库/帖子/xxx.md]]`

## content_type 合法值

方法论, 案例分析, 数据解读, 观点评论, 市场综述, 概念定义

> 注意：旧条目中可能出现的 `框架构建` 应归入 `方法论`，`案例研究` 应归入 `案例分析`，`数据记录` 应归入 `数据解读`，`观点解读` 应归入 `观点评论`。

## 标题命名规则

- 以知识概念命名（如「左侧交易者的多方向分散配置策略」）
- 不以事件/日期/原文标题命名
- 不以具体时间点锚定（如「6月24日上午盘面复盘」）

## 提炼原则

1. 忠于原文但可泛化——论点必须来自原文，但允许从具体案例提炼为一般性论点；具体案例作为佐证保留在论据中；论点本身不应依赖特定日期或事件才能成立
2. 结构化输出——使用模板格式
3. 来源可溯——每个观点标注来源
4. 增量更新——已有条目追加不覆盖
5. 多维度提炼——一篇素材产出多条维基条目，每条围绕一个核心概念
6. 交叉链接——关联条目双向互链
7. 去时间绑定——提炼后的论点和分析框架应独立于原始素材的具体日期和事件

## 交叉链接规则

- 新条目必须链接到所有相关已有条目
- 已有条目必须反向添加对新条目的链接
- wikilink 使用完整路径，不加 emoji 前缀
