# 维基审查

## Default Stance

### 核心原则
- **纯执行引擎**：所有参数由 pipeline 传入，不硬编码路径或规则。
- **全面覆盖**：审查必须覆盖所有传入的 dimensions，不遗漏条目。
- **可操作**：审查报告必须提取修复建议，按严重度排序，供用户选择执行。

### 禁止行为
- 绝不跳过任何审查维度
- 绝不在未确认的情况下自动修复条目
- 绝不遗漏条目（必须扫描目标目录全部文件）
- 绝不硬编码审查规则或阈值

---

## Workflow

**第一步**：读 {rules_path}，获取审查规则定义（维度阈值、合法值、正则模式、字段映射）
**第二步**：读 {template_path}，获取报告格式
**第三步**：读 BLOGGER_CONSOLE，获取全部博主注册信息
**第四步**：扫描 target_dir 全部条目
**第五步**：按 dimensions 逐项检查（含博主一致性对比）——判定标准从 rules_path 读取
**第六步**：按 {template_path} 生成报告
**第七步**：保存到 {output_dir}/YYYY年M月D日-审查.md
**第八步**：提取修复建议，用序号标注，询问用户需要修复哪些（不可跳过）

## 输入（全部必填）

{target_dir, dimensions, output_dir, template_path, rules_path, BLOGGER_CONSOLE}

## 审查维度

维度定义和判定标准全部从 {rules_path} 读取。当前支持的维度：

| 维度 | 检查内容 |
|:---|:---|
| 矛盾检测 | 同板块/个股条目间矛盾观点 |
| 时效检查 | time_sensitivity 对应周期 |
| 验证回溯 | validations 历史断言状态 |
| 孤立检测 | 无 backlinks 或从未被查询 |
| 质量检查 | 缺必填字段/文件过小/分类不匹配 |
| 时间绑定 | 标题/内容含具体日期或事件描述 |
| 博主一致性 | 控制台与画像是否一致 |

## 审查频率

| 类型 | 频率 |
|:---|:---|
| 全量审查 | 每周 |
| 增量审查 | 每次提炼后 |

## 修复建议与交互

报告生成后，必须：

1. 从报告中提取所有可修复的问题，按严重度排序（🔴 > 🟡 > ℹ️）
2. 用带序号的精简列表呈现修复建议，每条注明严重度、涉及条目数、预估工作量
3. **主动询问用户**：「需要修复其中哪几点？回复序号即可。」
4. 等待用户确认后再执行修复

## Output Format

审查产出为一个审查报告文件：
- 位置：`{output_dir}/YYYY年M月D日-审查.md`
- 内容：各维度检查结果 + 问题清单（含文件路径）+ 修复建议（按严重度排序）

## Relative Files

| 场景 | 加载文件 | 内容 |
|:---|:---|:---|
| 始终 | {template_path} | 审查报告模板 |
| 始终 | {rules_path} | 审查规则定义 |
| 始终 | BLOGGER_CONSOLE | 博主注册信息（用于一致性对比） |
