# 标签分类体系

标签核心原则：**归纳性描述**，回答"是什么类型"而非"涉及什么细节"。按需选用，不强制填满，宁精勿滥。

**标签与文件夹分类互补**：文件夹回答"这是什么类型的文件"，标签回答"内容涉及什么维度"。标签的价值在于捕捉文件夹分类无法表达的跨维度信息，使内容可被跨文件夹、跨博主筛选。判断标准：这个标签描述的是内容的真实特征，还是仅仅复述了文件夹的位置？如果是后者，不加。

**实体描述原则**：标签描述的是它所在实体的性质，不同实体类型用不同标签维度。
- 博主标签 → 描述人的特征（投资哲学、方法论、交易风格、身份）
- 个股标签 → 描述股票的特征（所属行业、所在市场）
- 方法论标签 → 描述方法的特征（框架类型）
- 心态/心得/交易体系标签 → 描述知识条目的特征（心理偏误、心得主题、体系类型）；允许跨分类引用分析框架标签标注方法论维度
- 行业/宏观标签 → 描述客观主题（行业分类、宏观事件）
- 博主不应带行业标签——博主关注的行业不等于博主本身的特征

**分层格式**：所有标签使用 `分类/子分类/标签` 三级格式（如 `投资心态/心理偏误/路径依赖`）。一级分类对应文件所属分类文件夹，在 Obsidian 标签面板中可按一级分类折叠浏览。

**前缀规则**：标签按内容实际特征选用，允许跨分类引用。例如投资心得文件可同时标注 `投资心得/心得主题/估值经验` + `分析框架/框架类型/周期分析框架`。默认前缀对应关系如下（非强制限制）：
- 博主画像文件 → 默认前缀 `博主/`
- 分析框架文件 → 默认前缀 `分析框架/`
- 投资心态文件 → 默认前缀 `投资心态/`
- 交易体系文件 → 默认前缀 `交易体系/`
- 投资心得文件 → 默认前缀 `投资心得/`，可按需引用 `分析框架/` 标签
- 行业文件 → 行业标签不加前缀（`行业/` 本身就是一级）
- 个股文件 → 行业 + 市场标签，不加前缀
- 宏观文件 → 通用标签不加前缀（`通用/` 本身就是一级）

**市场/行业标签使用规则**：`市场/` 和 `行业/` 标签仅在内容确实仅适用于特定市场/行业时添加。通用性的投资心得、心态、框架类内容不强制绑定市场/行业标签。个股文件天然绑定行业和市场，仍需添加。

## 编排规则

编排者根据文件的 category 字段确定默认标签前缀子集，refiner 按内容实际特征从中选用，并允许跨分类引用：

| 文件 category | 默认标签前缀 | 跨分类引用 |
|:---|:---|:---|
| 博主画像 | 博主/投资哲学/ + 博主/方法论/ + 博主/交易风格/ + 博主/身份/ | 不加行业标签 |
| 分析框架 | 分析框架/框架类型/ | 可加 市场/ + 行业/ |
| 交易体系 | 交易体系/体系类型/ | 可加 市场/ |
| 投资心态 | 投资心态/心理偏误/ 或 投资心态/心态修炼/ | 不加市场/行业（心态通用） |
| 投资心得 | 投资心得/心得主题/ | 可引用 分析框架/ 标签；仅在内容确实仅限特定市场/行业时加 市场/ + 行业/ |
| 个股 | 行业/ + 市场/（必须） | — |
| 行业 | 行业/ | — |
| 宏观 | 通用/ | 可加宏观事件/政策类型标签 |

refiner 不自造标签。发现现有标签无法准确描述时标注 `⚠️新标签建议`。
