# 审查规则

> 本文件是审查维度的唯一真相源。SKILL.md 的 workflow 引用此处定义，不重复描述。

## 内容审查

检查框架内容质量：

| 审查维度 | 检查什么 |
|:---|:---|
| 内部一致性 | 交易体系的规则和分析框架的方法论是否矛盾 |
| 知行合一 | 投资心态里写的纪律，实际交易中是否遵守了 |
| 我的框架 vs 博主框架 | 我的方法和博主的方法冲突时，标记出来让你判断 |
| 经验验证 | 投资心得里的教训，后续行为是否验证了 |
| 关联备注发现 | 为缺少跨条目关联的条目提议补充脚注（脚注类型和格式见 footnote-taxonomy.md），嵌入正文相关论述处 |

产出：审查报告，标记冲突项和待确认项。

## 结构审查

检查框架文件的组织和规范：

| 审查维度 | 检查什么 |
|:---|:---|
| 归类正确性 | 文件是否放在正确的归属层（我的/博主/其他）和分类下 |
| frontmatter 完整性 | 通用必填字段（title/createDate/updateDate/tags）+ 模板特定字段是否齐全 |
| 引号有效性 | frontmatter 中双引号包裹的值内部是否含未转义双引号（违反全局规则 #21） |
| wikilink 有效性 | 链接目标是否存在、双向互链是否完整 |
| 分类标签 | 标签是否匹配实际内容 |

产出：问题清单，标注需要修正的文件和具体问题。

## 审查频率

由用户手动触发，或后续设定定期执行。
