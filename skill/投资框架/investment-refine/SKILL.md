# 提炼执行器

---

## Default Stance

### 核心原则

- **两步模式**：先出方案报告供用户审阅，确认后再执行。绝不跳过方案直接创建文件
- **方案报告分条目卡片式**：每个拟产出条目一个独立区块，含元信息表格 + 拟写正文要点
- **可读性优先**：正文保留原文的比喻、案例、推理链条和生动表达。用自然语言段落而非干巴巴的要点罗列
- **忠实原文**：可重组表达、优化结构，但绝不捏造、编撰、偏离原文事实。比喻和案例必须来自原文
- **简体中文产出**：框架条目正文一律用简体中文。若原始资源仍为繁体（粗加工遗漏），提炼时作兜底繁转简，仅字形转换、不改用词语气
- **标签来自标签体系，与文件夹分类互补**：标签捕捉文件夹无法表达的跨维度信息，允许跨分类引用（如投资心得文件可标分析框架标签）。市场/行业标签仅在内容确实仅限特定市场/行业时添加，通用心得不强制绑定。标签宁精勿滥，不自造标签
- **条目间关联**：仅指同源多条条目之间的逻辑关联，在方案报告中标注关联方向；跨 vault 的关联备注在审查阶段处理。**提炼阶段不在文件中创建任何关联章节**——既不输出 `## 关联` 章节，也不输出空脚注占位。条目间关联的正式落地是审查阶段写入文末 `---` 脚注区的关联脚注（`[^enhance-N]`/`[^complement-N]` 等，见 footnote-taxonomy.md）
- **模板驱动**：执行时每个条目必须使用对应分类的模板填写 frontmatter + 正文
- **参数全部由编排者传入**：缺参即报错

### 禁止行为

- 绝不跳过方案报告直接创建框架条目
- 绝不在"我的"层创建或修改文件
- 绝不遗漏博主行的处理（如涉及已登记博主，必须同时更新博主档案）
- 绝不将非投资内容放入"其他"层
- 绝不使用标签体系外的标签
- 绝不捏造、编撰原文没有的内容——比喻和案例必须来自原文

## Workflow

### 前置条件（由编排者保障）

本 skill 的输入必须来自 `工作区/原始资源/` 且 `status=待提炼`。编排者需在调用前确认：

- 原始资源中已存在该文档且 `status=待提炼` → 直接进入本 skill 两步模式。
- 原始资源中**不存在**该文档（无 `status=待提炼` 记录）→ 说明仍在 `工作区/粗制品/`，编排者应先调用 `investment-coarse-processor` 粗加工（置 `status=待提炼`），再进入本 skill。**本 skill 不处理粗制品。**

### 第一步：提炼分析 → 生成方案报告

读取原始资源全文，分析内容后生成提炼方案报告，输出到对话中（不写文件）。

报告格式——分条目卡片式：

```markdown
## 提炼方案

**来源**：[[工作区/原始资源/xxx]]（可多个，对应产出文件 `source` 数组）
**作者**：xxx | **日期**：xxx

---

### 条目 1

| 字段 | 内容 |
|:---|:---|
| 归属层 | 其他 |
| 分类 | 投资心态 |
| 建议标题 | {标题} |
| 标签 | {从标签体系选，如 投资心态/心态修炼/耐心} |
| 拟用模板 | 投资心态 |
| 内容摘要 | {一句话} |
| 条目间关联 | → 条目2（关联说明） |

**拟写正文要点**：
- {要点1}
- {要点2}

---

### 条目 2
...
```

报告设计原则：

- 分条目卡片式，每个条目一个独立区块
- 表格呈现元信息：归属层、分类、标题、标签、模板一目了然
- 标签必须来自标签体系（investment-framework/references/tag-taxonomy.md），允许跨分类引用（如投资心得可标分析框架标签）；通用心得/心态不强制加市场/行业标签
- 条目间有逻辑关联的标注关联方向
- 拟写正文要点列出计划写入的关键内容
- 便于批改：用户可直接回复"条目1标题改为XX"、"条目2不要了"等

### 第二步：用户确认 → 提炼执行

用户审阅方案报告后：

- **直接确认**：按方案逐条创建框架条目文件
- **提出修改**：按用户反馈调整后重新展示，确认后再执行
- **取消**：不执行任何操作

执行时：

1. 按方案中的归属层和分类确定文件路径
2. 选择对应模板（从编排者传入的 templates）
3. 创建文件，填写 frontmatter + 正文内容。正文按模板中的写作指引，保留原文的比喻、案例、推理链条，用自然语言段落而非干巴巴的要点罗列
4. 条目间关联在方案报告（对话）中标注方向即可，**不在文件中创建 `## 关联` 章节或空脚注占位**。该关联的正式落地是审查阶段写入文末 `---` 脚注区的关联脚注（`[^enhance-N]`/`[^complement-N]` 等，见 footnote-taxonomy.md）。仅当正文确有具体数据/时效判断时，提炼阶段才输出 `---` 脚注区并填 `[^data-N]`/`[^date-N]`（脚注区以 `---` 分隔线标识，无 `## 脚注` 标题）
5. 如涉及已登记博主，读取 `博主/{博主名}/{博主名}.md`，在信息汇总章节追加本次条目
6. 如涉及宏观事件：通用宏观框架放 `宏观/`，博主的具体宏观分析放 `博主/{博主名}/宏观/`，填写 `event` 字段以便跨博主聚合，并在传导路径中关联行业/个股 wikilink
7. 将原始资源文件的 status 改为 `已提炼`

## 自检

- [ ] 源文件是否在原始资源中且 `status=待提炼`？若否，是否已先从粗制品完成粗加工？
- [ ] 方案报告是否已输出到对话中供用户审阅？
- [ ] 用户是否已确认方案（或提出修改）？
- [ ] 产出正文是否为简体中文（若原始资源为繁体，是否已兜底转换）？
- [ ] 每个条目的标签是否来自标签体系？
- [ ] 每个条目是否使用了正确的模板？
- [ ] frontmatter 字段是否完整？
- [ ] 如涉及博主，博主档案是否已更新？
- [ ] 如涉及宏观，传导路径 wikilink 是否已添加？
- [ ] 提炼产出文件是否未含 `## 关联` 章节、未含空脚注占位？（条目间关联仅在方案报告中标注方向，正式落地为审查阶段文末 `---` 脚注区的关联脚注）
- [ ] 是否在"我的"层创建了文件？（应该没有）
