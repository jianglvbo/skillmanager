# docx-template-fill

## Default stance

核心原则：

1. **格式不变的唯一保证是「只改文本」** —— 除下述两处例外，不得调用任何格式类工具；新增文本靠继承既有段落属性获得格式
   - 例外一：模板子标题下没有内容槽位时，用 `doc_insert_paragraph_with_text(level=0)` 补普通段落
   - 例外二：模板提示段是「提示样式」（如仿宋 16pt 斜体）而模板规范要求正文「宋体小四」时，对**填入内容**做字体归一化；模板原有元素一律不动
2. **替换目标一次性定位、降序执行** —— 所有 `doc_find` 必须在**任何编辑之前**完成，再按 `begin` 降序 `doc_replace_text`；边找边改必然因文本长度变化而错位
3. **插入位置在编辑之后重新解析** —— 锚点插入的坐标不能沿用编辑前的快照，必须编辑完成后重新 `doc_resolve_document_structure`
4. **表格用当前顺序解析 `table_id`** —— 多次编辑后旧 `table_id` 会失效（报 `table_id not found`），必须重新 `doc_list_tables` 按序取用
5. **填表前先核对首行是不是表头** —— 表头行与数据行的起点差一行，填错会覆盖表头并把数据整体上移
6. **多段内容要拆成多段插入** —— `doc_replace_text` 只写一段，其余段落用 `doc_insert_paragraph_with_text` 顺次补，不能靠 `\n`
7. **模板原件不动** —— 复制成目标文件后只编辑副本，模板保持字节级不变
8. **交付前必须举证格式未变** —— 逐层比对页面设置 / 标题字体 / 样式表 / 表格底色 / 填入内容的字体

禁止行为：

1. **禁止为了「好看」调整字体字号或对齐** —— 用户要的是模板原样，不是重新设计
2. **禁止删除段落来清理提示行** —— 用文本置空代替 `doc_delete_paragraph`，避免结构与坐标变动
3. **禁止把 `doc_replace_text` 的参数写成 `begin`/`end`** —— 它是 `ranges: [{begin, end}]` + `text`
4. **禁止用长串或非唯一串做定位** —— 结构预览在 compact 模式仅回约 4 字，且 `doc_find` 只取首个命中，match 必须短且唯一
5. **禁止在未确认模板占位结构前动手** —— 先取全文与结构坐标，确认每个占位的段落范围与表格维度

## Workflow

第一步：读模板 —— 用 `scripts/extract_docx_text.py`（来自 `docx-from-markdown` skill）取模板全文，看清占位符、表格维度与提示语

第二步：取结构坐标 —— `doc_resolve_document_structure mode=full text_preview_length=200 limit=0`，导出每个占位段落的 `start_index/end_index` 与表格 `table_id`，落盘备用

第三步：核对页面与样式基线 —— `doc_get_section_property` + 标题/正文字体 + 表格表头底色，记录下来作为交付前的比对基准

第四步：写填充配置 —— `fill.json`（见下节字段），edits 的 `match` 用占位原文的短片段

第五步：执行 —— `python3 scripts/fill_template.py fill.json`（脚本内部：复制模板 → 定位 → 降序替换 → 锚点插入 → 插图 → 填表 → 字体归一化 → 保存）

第六步：回读校验内容 —— 提取成品全文，确认占位符 0 残留、模板提示语全部清除、各章节内容到位

第七步：举证格式未变 —— 比对模板与成品的：页面设置、标题 run 属性、styles.xml（按样式名比属性，忽略序列化顺序与 styleId 重映射）、表格单元格底色、填入内容的字体

第八步：清理实例 —— `close_file` 后台实例；未保存的实例需 `force=true`

### 决策点

- **模板子标题下没有空段落槽位** → 用 `anchor_inserts` 的 `mode: "after_heading"`，在标题段后插入 `level=0` 的普通段落；不要硬塞进别处
- **模板提示段与目标正文字体不一致**（提示段仿宋 16pt 斜体、规范要求宋体小四）→ 以「模板自己的规范 + 已通过验收的同类成品」为准做归一化，并在交付说明里写明只作用于填入内容
- **一段内容含多个自然段** → 首段用 `doc_replace_text`，其余段落依次 `doc_insert_paragraph_with_text`；`\n` 不会产生新段落
- **锚点后连续空段落不足** → 说明该处没有预留槽位，改用 `after_heading`，不要插到别的段落后（会继承错误格式）
- **目标文件名与模板规范冲突**（如模板要求「智能体开题报告+【队伍名称】+【方案名称】.docx」）→ 按模板规范命名，并先确认不与已有文件重名
- **模板附录/参考页是否保留** → 默认保留（属模板组成部分），交付时显式提示用户可删

## Output format

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| 模板路径 | string | 原件，须保持未被修改 |
| 成品路径 | string | 填充结果，独立文件 |
| 替换处数 | int | edits 命中数，须等于配置条数 |
| 占位残留 | int | 成品中 `XXXX` 等占位数量，应为 0 |
| 格式比对 | string | 逐层比对结论：一致 / 差异项 |

## 自检

- [ ] 模板原件字节未变（大小/时间戳）？成品为独立文件？
- [ ] 成品占位符 0 残留，且不含模板提示语（如「请简要概括…」「如果有多个场景…」）？
- [ ] 填表时首行表头未被覆盖、数据行号与模板一致？
- [ ] 子标题下的内容落在该子标题之后（没串到别的段落里）？图片在题注之前？
- [ ] 页面设置、标题字体、样式表属性、表格底色、附录表与模板一致？
- [ ] 填入内容的字体已按模板规范统一（宋体 12pt、非斜体、非加粗）？
- [ ] 后台实例已清理？
