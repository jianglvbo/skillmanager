# 八大设计原则

## 原则一：职责单一

一个 Skill = 一个明确的领域。复杂流程拆成多个 Skill 串联。

❌ 一个 Skill 同时处理行情、财报、博主
✅ 拆成 stock-analyzer、link-analysis、blogger-refine

## 原则二：精准描述

`description` 是 Agent 选择 Skill 的唯一依据。含触发词 + 排除条件 + 与相邻 Skill 的区别。

## 原则三：确定性优先

编号清单 > 自然语言。决策树 > if-else 描述。模板 > 自由格式。脚本执行 > AI 模拟。

## 原则四：渐进式披露（三层加载机制）

```
YAML 门控: 始终在上下文（~100 字）
SKILL.md 正文: 触发时加载（≤200 行）
references/: 按需检索读取（消耗 Token）
scripts/: 按需执行（不读代码，只看输出，极省 Token）
```

核心：AI 平时只带轻量级"索引"工作，细节按需加载。这是认知卸载（Cognitive Offloading）的实现。

## 原则五：分层执行（Hierarchical Execution）

Reference 让 AI "读"（消耗 Token，像翻附录），Script 让 AI "做"（消耗算力，像用量具测量）。

- **计算结果精准**（格式检查、数据校验、文件操作）→ 用 Script 执行
- **需要理解和判断**（规则解释、决策指引）→ 用 Reference 读取
- **绝不让 AI 脑补机械性验证**

## 原则六：人类主导

方法论和判断标准由人定义。模型只做格式化和补全。

## 原则七：内置验证

每个 Skill 结尾必须含自检清单。任一不通过，回溯修正。

## 原则八：安全边界

限制工具范围、敏感数据只读、外部操作需确认。

## 原则九：标准化输出

输出 = API 接口。字段固定、类型固定、顺序固定。
