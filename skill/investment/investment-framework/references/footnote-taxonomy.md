# 脚注分类体系

> 脚注是正文的补充，不是正文的替代品。
> 与 tag-taxonomy.md 同级，是脚注使用的唯一真相源。

## 核心原则

1. **补充而非替代**：脚注提供正文无法容纳的补充信息，不应干扰正文阅读流
2. **有必要才加**：不为加脚注而加，每条脚注都应有明确目的
3. **标签英文命名**：脚注标签用英文关系类型命名，同类递增（`[^type-1]`, `[^type-2]`...）
4. **位置紧贴相关论述**：脚注标记放在正文中相关句子/数据之后，标点之前
5. **定义统一放文末**：所有脚注定义集中在文件末尾（无 `## 脚注` 标题、**无 `---` 分隔线**——Obsidian 阅读模式会自动为脚注区渲染分割线，手动加 `---` 会重复，2026-08-09 用户确认）

## 禁止行为（硬约束）

1. **禁止非法标签名**：脚注标签前缀只允许 `enhance` / `supplement` / `conflict` / `complement` / `opposite` / `data` / `date` 七种。禁止使用 `关联`、`ref`、`note`、`来源` 等自造标签
2. **禁止标签与描述不一致**：标签前缀必须与定义中的中文关系词严格对应（enhance=增强、supplement=补充、conflict=冲突、complement=互补、opposite=对立）。写"补充"就必须用 `supplement`，不得用 `enhance`
3. **禁止孤儿脚注**：每条脚注定义必须有对应的正文内联标记；反之每条内联标记必须有文末定义。只有定义无标记 = 孤儿，只有标记无定义 = 悬空，两者均为格式错误
4. **禁止正文末尾来源 blockquote**：来源信息一律写入 frontmatter `source` 字段，禁止在正文末尾（脚注定义前后）添加 `> 来源：...` 形式的 blockquote
5. **模板是纯结构骨架，产出文件不留解释成分**：模板（`assets/*.md`）只含字段骨架 + section 标题 + 表格表头，**不含任何解释**（花括号占位 `{...}`、blockquote 指引、表格示例行、frontmatter 行内注释）。各 section 的写作指引统一在 `references/template-guide.md`，全局规则在 framework-rules/tag-taxonomy/本文件。产出文件可保留模板的空结构（空 section 标题、空表格表头）——**空结构合法**；但不得出现以下残留（verify-format.py 检测，可 `--fix`）：
   - **花括号占位**：`{作者名}`、`{YYYY-MM-DD}` 等 `{...}` 指引文本；
   - **blockquote 指引**：`> 原文链接必填...`、`> 示例：...`、`> - **操作**枚举...` 等 `>` 指引行；
   - **frontmatter 行内注释**：`star: false  # 好文章标记...`、`delete:  # 待删除标记...` 等 `#` 注释；
   - **全空表格占位行**：`| | | | |`（全空单元格行）；表格无数据时保留表头、不建占位行。
   - **判定辅助**：模板中任何 `{...}`、`# 注释`、`> 指引`、示例数据行都是模板成分；正式文件出现即视为模板残留（存量 308 文件 `delete:` 行尾注释即此泄漏，2026-08-08 清理）。
6. **脚注 wikilink 目标仅限 wiki 产物（硬约束）**：脚注是 wiki 产物之间的互相引用，**禁止以任何形式（含 wikilink）指向 `工作区/` 文件夹下的任何文件**——原始资源、粗制品、博主控制台等均不可作为脚注目标。
   - **关联类脚注**（enhance/supplement/conflict/complement/opposite）目标必须是另一条 wiki 产物（`我的/`、`博主/`、`其他/`、`宏观/` 下的框架条目或博主档案）；
   - **数据溯源脚注**（data）的来源写**纯文本描述**（来源名称 + 数据描述 + 截止日期），禁止用 wikilink 指向原始资源——原始资源的溯源职责由 frontmatter `source` 字段承担（内部来源用 `[[工作区/原始资源/...]]` wikilink，见 framework-rules #23）；
   - 原因：原始资源是提炼的中间产物，指向它既冗余（source 已承载溯源）又会在 wiki 产物与工作区之间制造错误的关联连线。

## 脚注分类

| 大类 | 标签 | 用途 | 添加阶段 | 添加位置 |
|:---|:---|:---|:---|:---|
| 关联 | `[^enhance-N]` | 另一条目增强/支持本条论点 | review | 正文相关论述处 |
| 关联 | `[^supplement-N]` | 另一条目补充了本条内容 | review | 正文相关论述处 |
| 关联 | `[^conflict-N]` | 另一条目与本条存在张力/矛盾 | review | 正文相关论述处 |
| 关联 | `[^complement-N]` | 另一条目与本条互补 | review | 正文相关论述处 |
| 关联 | `[^opposite-N]` | 另一条目与本条观点/规则直接对立 | review | 正文相关论述处 |
| 数据溯源 | `[^data-N]` | 标注具体数据的来源和截止日期 | 提炼 | 引用具体数据/统计处 |
| 时效标注 | `[^date-N]` | 标注信息的时间适用范围和失效条件 | 提炼 | 时间敏感的判断/结论处 |

## 一、关联脚注

### 何时添加
在 **审查（review）阶段** 发现跨条目知识关联时添加。提炼阶段不做关联——避免每次提炼都扫描整个 vault。

### 标签定义

| 标签 | 含义 | 使用场景 |
|:---|:---|:---|
| `[^enhance-N]` | 增强 | 另一条目提供了更多证据或更强论证，支持本条观点 |
| `[^supplement-N]` | 补充 | 另一条目提供了本条未涉及的角度或额外信息 |
| `[^conflict-N]` | 冲突 | 另一条目与本条存在观点张力或矛盾，需要读者注意 |
| `[^complement-N]` | 互补 | 另一条目与本条配合使用更完整，各覆盖不同侧面 |
| `[^opposite-N]` | 对立 | 另一条目与本条观点/操作规则**直接对立**——非此即彼，照做会得到相反动作（如"允许补仓 vs 绝不补仓"、"买 vs 不买"），无调和空间（2026-08-08 新增） |

### 冲突 vs 对立（区分标准 · 2026-08-08 用户确认）

| 维度 | conflict（冲突） | opposite（对立） |
|:---|:---|:---|
| 关系强度 | 有张力/前提不同，可调和 | 非此即彼，直接相反 |
| 实际后果 | 各有道理，需读者权衡 | 照做会得到**相反动作** |
| 示例 | 追高 vs 不追高（同一认知，强度不同） | 允许纠错补买 vs 绝不补仓（YES vs NO） |

> 判据：若两条规则在**同一情境**下会给出**相反的操作指令**，用 `opposite`；若只是观点侧重不同/有前提差异、未必行动相反，用 `conflict`。

### 格式规范

正文标记：在相关论述的句子末尾、标点之前插入 `[^type-N]`。

脚注定义（文件末尾，无 `---` 分隔线、无 `## 脚注` 标题）：

```
[^enhance-1]: [[博主/段永平/投资心得/买股票就是买公司]] — 增强：段永平从企业主角度给出了更强的论证
[^conflict-1]: [[其他/投资心得/错过'时代'是最大的风险]] — 冲突：该文认为应积极追趋势，与本条"不追高"的观点存在张力
[^opposite-1]: [[我的/交易体系/买卖纪律]] — 对立：本条"绝不补仓"与买卖纪律"分两次买入、纠错降本"在补仓动作上直接相反
```

### 注意事项
- 每条关联脚注必须有 **内容层面的依据**，不可编撰关系（校验方法见「关系依据校验」）
- 同类脚注递增编号：`[^enhance-1]`, `[^enhance-2]`...
- 关联脚注由 review skill 发现并提出，用户确认后才写入

### 格式校验（审查必查）

- 脚注定义中的 wikilink **必须以单个 `]]` 闭合**；出现 `]]]` 或多余 `]]`（如 `...买股票就是买公司]]` 末尾多一个 `]`）一律判为格式错误，需删去多余括号
- 完整格式：`[^type-N]: [[target]] — 关系：一句话说明`，`—` 前后各一个空格，关系类型用中文（增强/补充/冲突/互补/对立）
- 正文内联标记 `[^type-N]` 必须存在且与文末定义一一对应；**只有定义无内联标记的脚注为孤儿脚注**，需补内联标记或删除

### 关系依据校验（审查必查）

- 审查阶段除发现新关联外，**必须复核文件中已存在的每条关联脚注**
- 校验方法：打开关系声明指向的目标文件，确认其原文确实支撑该关系
  - 增强：目标提供了更强论证或更多证据
  - 冲突：目标与本条存在真实观点张力（非臆测）
  - 互补：目标与本条覆盖不同侧面、配合使用更完整
  - 对立：目标与本条在**同一情境**下给出**相反的操作指令**（非臆测；有前提差异可调和则降级为 conflict）
- 若目标文件**不含支撑该关系的原文内容**，标记为 **编撰关系**，在报告中建议二选一：
  1. 删除该脚注；或
  2. 降级为 `[^enhance-N]`（仅表示"相关"，不声称特定关系）
- 严禁保留无原文依据的冲突/互补/对立声明——这会让框架呈现虚假对立，误导后续决策

## 二、数据溯源脚注

### 何时添加
在 **提炼阶段**，当正文引用了具体数据、统计数字、财务指标或事实性声明时添加。

### 格式规范

```
[^data-N]: 来源名称 — 数据描述，截至YYYY年M月
```

### 示例

正文：
> 海螺水泥资产负债率仅28.5%[^data-1]，现金流净额连续五年为正。

脚注定义：
```
[^data-1]: 海螺水泥2025年年报 — 资产负债率28.5%，截至2025年12月
```

### 注意事项
- 必须标注数据截止日期，帮助读者判断时效性
- 来源可以是年报、研报、博主原文、官方统计等
- 常识性内容（如"茅台是白酒龙头"）不加数据溯源脚注
- 来源信息应足够具体，读者可据此查证

## 三、时效标注脚注

### 何时添加
在 **提炼阶段**，当正文包含时间敏感的判断或结论时添加。帮助读者快速判断信息是否还"保鲜"。

### 格式规范

```
[^date-N]: 截至YYYY年M月 — 后续需关注{关键变量}是否改变结论
```

### 示例

正文：
> 当前市场几乎没人给这个期权定价[^date-1]。

脚注定义：
```
[^date-1]: 截至2026年7月 — 后续需关注房地产企稳进展和碳中和政策变化，若行业出现结构性衰退则"周期性"判断失效
```

### 适用场景
- 基于当前市场状态的判断（如"当前估值处于历史低位"）
- 依赖特定宏观环境的结论（如"在降息周期中"）
- 涉及具体数值阈值的观点（如"股息率超过4%就有吸引力"）
- 政策相关判断（如"在碳中和限产背景下"）

### 不适用场景
- 纯方法论/框架性内容（如分析方法的步骤说明）
- 定义性内容（如概念解释）
- 长期适用的基本原则

---

## 脚注排列顺序

当同一文件包含多种脚注时，文末脚注定义（无 `---` 分隔线）按以下顺序排列：

1. 关联脚注（enhance → supplement → conflict → complement → opposite）
2. 数据溯源脚注（data）
3. 时效标注脚注（date）

同类脚注按编号递增排列。
