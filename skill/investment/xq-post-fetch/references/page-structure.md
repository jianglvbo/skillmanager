# 雪球用户页 Markdown 结构解析

本文档描述 `browser-act get markdown` 返回的用户页 markdown 中，帖子内容的识别和提取规则。

---

## 帖子在 markdown 中的结构

每个帖子块由以下元素组成（按出现顺序）：

```
[头像图片](用户主页链接)
[作者名](用户主页链接)[时间戳· 来自设备](帖子链接)
正文内容...
[*转发]()[*回复数]()[*点赞数]()[*收藏]()
[*投诉]()
```

### 关键识别点

1. **帖子链接** = `https://xueqiu.com/{xq_id}/{post_id}` — 这是提取 post_id 的唯一来源
2. **时间戳** 紧跟在作者名后面，格式为 `[时间文本](帖子链接)`
3. **正文** 在时间戳行和互动按钮行之间
4. **互动按钮行** 以 `[*转发]()` 开头，包含 4 个按钮：转发、回复(n)、点赞(n)、收藏

### 与页面噪声的区分

用户页 markdown 包含大量非帖子内容，需要过滤：

| 噪声类型 | 特征 | 过滤方式 |
|:---|:---|:---|
| 顶部导航 | `首页`、`股票`、`用户`、`组合`、`猜你想搜` | 跳过第一个帖子之前的所有内容 |
| 用户信息区 | `关注`、`粉丝`、`IP属地`、签名、分享按钮 | 跳过帖子链接之前的 profile 区域 |
| Tab 导航 | `帖子29620`、`回复`、`收藏`、`自选`、`组合` | 跳过 |
| 筛选 Tab | `全部`、`热门`、`原发`、`长文` | 跳过 |
| 推荐用户 | `用户推荐[换一换]` + 头像列表 | 跳过帖子之后的推荐区域 |
| 页脚 | `风险提示`、`© 2026 XUEQIU.COM`、备案信息 | 跳过 |
| 安全警告弹窗 | `账号安全等级低`、`绑定手机号` | 跳过 |
| 登录弹窗 | `微信扫码支付` | 跳过 |

**识别帖子区域的边界**：从第一个包含 `xueqiu.com/{xq_id}/\d+` 链接的块开始，到 `### 她的认证` 或 `### 用户推荐` 之前结束。

## Post ID 提取

post_id 嵌在帖子时间戳的超链接中：

```
[metalslime](https://xueqiu.com/2292705444)[2小时前· 来自雪球](https://xueqiu.com/2292705444/400908222)
```

提取规则：从 `https://xueqiu.com/{xq_id}/(\d+)` 正则匹配，捕获组即为 post_id。

注意区分：
- `https://xueqiu.com/u/2292705444` → 用户主页链接（含 `/u/`），**不是**帖子链接
- `https://xueqiu.com/2292705444/400908222` → 帖子链接（无 `/u/`），提取 `400908222`

**时间戳行前缀陷阱（2026-08-15 实战教训）**：时间戳链接前常带作者名前缀，如：
```
[柯中](https://xueqiu.com/cozone)![头像](...) "荣誉认证"[修改于昨天 15:04· 来自Android](https://xueqiu.com/5243796549/405069975)
```
**禁止用行首锚定 `^` 正则匹配时间戳**（`re.match` 会匹配 0 条）——必须用 `re.search`/`findall` 全局搜索时间戳模式 `\[[^\]]*· 来自[^\]]*\]\(https://xueqiu.com/{xq_id}/(\d+)\)`。

## 时间格式转换

用户页中帖子的时间有 5 种格式，需统一转为绝对时间：

| 格式 | 示例 | 转换规则 |
|:---|:---|:---|
| 完整日期 | `修改于2025-07-27 11:59` | 直接解析 YYYY-MM-DD HH:MM（**置顶帖/专栏帖常见**，缺此格式会把旧帖误判为新帖） |
| N小时前 | `2小时前` | `当前时间 - N小时` |
| N分钟前 | `30分钟前` | `当前时间 - N分钟` |
| 昨天 HH:MM | `昨天 23:35` | `昨天日期 + 时间` |
| MM-DD HH:MM | `07-16 14:06` | 当年日期（用于引用块中的时间） |
| 置顶帖 | `2025-07-27 11:59` | 完整日期 + 链接后「置顶」标记，**不纳入时间窗口** |

**前置条件**：在解析时间前，先调用 `date "+%Y-%m-%d %H:%M"` 获取当前绝对时间作为基准。

**注意**：`N小时前`/`N分钟前` 是模糊时间，实际发布可能有几分钟误差。对于需要精确时间的场景（如去重），以详情页显示的发布时间为准。

## 置顶帖识别（2026-08-15 实战修正）

**API 路径**：置顶帖的 `pinned` 字段**不可靠**（常为 `None`/缺失），且 `text` 常为空字符串、时间戳可能是旧日期。判断置顶帖的可靠方式：
- 时间远早于采集窗口（如 2025 年日期出现在 2026 年窗口中）
- `mark: 1` 字段（有值时即置顶）
- 页面侧：时间戳链接后带「置顶」文本（`](...post_id)置顶`）

**边界判断陷阱**：用「最早帖子时间 < cutoff」判断翻页停止时，**必须先排除置顶帖**（置顶帖时间极旧会误触发 BOUNDARY，导致只采 1 页）。更稳的策略：固定拉取页数（如 5 页）后在本地按 cutoff 过滤，不做逐页边界判断。

## 互动数据提取

用户页的互动按钮 markdown 格式：

```
[*转发]()[*61]()[*362]()[*收藏]()
```

或带空链接的变体：

```
[*][*61]()[*362]()[*收藏]()
```

解析规则：
1. 找到以 `转发` 开头的按钮行
2. 4 个按钮依次为：转发、回复(n)、点赞(n)、收藏
3. 转发数：如果 `转发` 后面紧跟 `()` 无数字 → 0；有数字则提取
4. 回复数：第 2 个按钮中的数字
5. 点赞数：第 3 个按钮中的数字
6. 收藏：忽略（不提取）

**注意**：用户页的互动数据可能与详情页略有差异（页面缓存），以详情页为准。

## 截断检测

以下标记表示帖子内容被截断，需要导航到详情页补全：

| 标记 | 说明 |
|:---|:---|
| `[展开]()` | 明确的截断标记，几乎 100% 表示有更多内容 |
| `[收起]()` | 出现在引用块前，表示引用块可折叠，**不是**正文截断 |
| 末尾 `...` | 标题或正文以省略号结尾 |
| 正文只有 1-2 行但引用块很长 | 可能是回复帖，正文本身就这么短，不算截断 |

**判断逻辑**：
1. 有 `[展开]()` → **确定截断**，必须导航详情页
2. 无 `[展开]()` 但正文看起来不完整 → **可能截断**，导航详情页确认
3. 回复帖正文短但完整（有完整句子结尾） → **不截断**，保留摘要

## 引用内容处理

帖子中常包含引用块（`>` 开头的 markdown），来源有三种：

| 来源 | 特征 | 处理方式 |
|:---|:---|:---|
| 被回复者的原文 | `> [@用户名：](链接)` 开头 | 保留，用 `> ` 引用格式标注 |
| 关联帖子的内容 | `> [@用户名：](链接)` + 时间/互动数据 | 保留，标注来源 |
| 7X24 快讯等系统引用 | `> 7X24快讯：` 或 `> 收起` | 保留，作为上下文 |

**输出格式**：引用内容保留在正文中，用 `>` 前缀。作者自己的回复/原创内容不加 `>` 前缀。

## Emoji 处理

雪球表情在 markdown 中的格式：

```
![吐血](https://assets.imedao.com/ugc/images/face_regular/v1/emoji_23_blood.png?v=1 "[吐血]")
```

处理规则：将整个 `![...](...)` 替换为 `[表情名]`，从 title 属性或 alt text 中提取。

简化正则：`!\[([^\]]*)\]\([^)]*"\[([^\]]*)\]"[^)]*\)` → `[$2]`

> **保持原文原则（2026-08-09 用户确认边界）**：emoji 限制只影响 wiki 产物（提炼环节），**采集与粗加工必须保持原文**——所有表情一律保留为 `[表情名]` 文本占位，**禁止删除**（即使不影响语义理解）；Unicode 表情字符（如 👍😄）原样保留，不做任何清洗。
