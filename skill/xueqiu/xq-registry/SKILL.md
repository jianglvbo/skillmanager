# 雪球博主投资思维 · 统一中控

> 多位雪球博主，一个注册表，全局掌控。

## 身份识别

- **技能名**: xq-registry
- **中控位置**: `~/Ai/skill/xueqiu/xq-registry/`
- **数据文件**: `~/Ai/skill/xueqiu/xq-registry/registry.json`
- **管理的 Skills**: `~/Ai/skill/xueqiu/xq-{拼音昵称}/` 目录下所有博主技能（数量动态，见 registry.json）

## 🚨 路由层（最高优先级）

> Skill 涨到上百个后，路由就是检索问题。所有 xq-* 博主的请求**不得平铺竞争**。

本 Skill 是雪球博主体系的**统一路由入口**。Agent 遇到与雪球博主相关的咨询请求时，**必须**先经过本 Skill 做博主匹配，匹配确认后再加载对应 xq-{id} Skill。

### 路由流程

```
用户请求
  ↓
第一层：这是雪球博主咨询类请求吗？
  ├── 是 → 进入第二层
  └── 否 → 不加载本 Skill，也不加载任何 xq-* Skill（见负样本表）
  ↓
第二层：能精确匹配到博主吗？
  ├── 用户指定了昵称/ID → registry.json 精确匹配
  └── 用户描述了风格/板块/市场 → 按分组/风格/板块推荐 Top 3-5
  ↓
第三层：加载对应 xq-{id} Skill，用该博主框架回答问题
```

### 路由指令（给 Agent）

1. 接收到雪球博主相关请求时，**优先加载本 Skill（xq-registry）**，而非直接加载具体 xq-* Skill
2. 在 registry.json 中完成博主匹配（精确匹配或分组推荐）
3. 匹配成功后，**再**加载对应的 xq-{id} Skill 完成任务
4. 多博主场景：先在本 Skill 内完成博主组合推荐，让用户确认后逐一加载
5. 匹配不到博主 → 诚实告知，禁止强行匹配

### 负样本：什么时候不触发

以下情况**不要**加载本 Skill 或任何 xq-* Skill：

| 场景 | 示例 | 原因 |
|------|------|------|
| 随口提到 | "我之前刷到过鹿鼎公的帖子" | 闲聊提及，不是咨询 |
| 平台讨论 | "雪球这个功能怎么用" | 讨论的是平台，不是博主观点 |
| 纯数据查询 | "雪球上茅台讨论热度怎么样" | 要的是平台数据，不是博主分析 |
| 技能本身 | "帮我更新一下 xq-xxx 的 SKILL.md" | 是在操作 Skill，不是咨询投资 |
| 非投资场景 | "这个博主是哪里人" | 问的是个人信息，不是投资观点 |
| 博主已锁定 | "用 APEC蓝天的框架分析茅台" | 用户已明确指定博主 → 直接加载对应 Skill，不需路由 |

### 博主无法匹配时

registry.json 中找不到匹配的博主：
- 诚实告知「这位博主不在当前注册表中」
- 提示：「需要我抓取这位新博主吗？」
- **禁止**：强行匹配一个不相关的博主、编造博主观点

## 核心能力

### 1. 注册表查询

读取 `registry.json` 回答用户关于博主的任何问题：

- **按名字找**: 输入昵称或雪球ID → 返回完整档案
- **按分组找**: 「港股达人都谁？」「价值投资派有哪些人？」
- **按风格找**: 「谁擅长困境反转？」「谁关注科技赛道？」
- **状态总览**: 多少人完整画像、多少人待补全、总共分析多少帖子

查询时直接读取 registry.json，用 python3 或 jq 做过滤，输出格式友好的表格。

### 2. 改名检测与自动更新

当用户说「检查博主改名」或触发更新时，执行以下流程：

```
步骤 1: 读取 registry.json 中所有博主的 xueqiu_id 和当前 nickname
步骤 2: 对每个博主，访问 https://xueqiu.com/u/{xueqiu_id} 获取主页上的最新昵称
步骤 3: 比较最新昵称与 registry 中记录的 nickname
步骤 4: 发现不一致时：
  a. 在 registry.json 的 name_change_log 中记录变更（含时间戳、旧名、新名）
  b. 更新 registry.json 中该博主的 nickname 字段
  c. 更新对应 SKILL.md 中所有出现旧昵称的位置：
     - YAML frontmatter description（第 1 行和第 3 行触发词）
     - 身份识别段落中的「当前昵称」
     - 角色扮演规则中的称呼
     - 标题行
  d. 通知用户变更详情
```

**批量检测时注意**：每次访问雪球主页之间间隔 2-3 秒，避免触发反爬。优先检测 `info_cutoff` 较旧的博主。

### 3. 使用频次追踪

**记录规则**：每当用户在对话中调用某个 xq-* 博主的 skill（通过提到博主名字、ID 等方式），在 registry.json 的 `usage_log` 数组中追加一条记录：

```json
{
  "skill_name": "xq-guanwocai",
  "nickname": "管我财",
  "timestamp": "2026-06-05T14:30:00",
  "action": "query",
  "topic": "港股分红策略"
}
```

action 类型：`query`（咨询观点）、`update`（更新画像）、`compare`（联合分析中被调用）

**报告功能**：当用户说「我的关注权重」或「使用统计」时，统计并展示：

- 近 7 天 / 30 天 / 全部 的博主调用排行
- 按 topic 聚合的热门话题
- 从未被调用过的博主列表（冷板凳）
- 使用频率与博主分组的交叉分析

### 4. 博主分组与标签

registry.json 中的 `groups` 字段包含自动生成的分组（数量动态，以下为当前快照）：

- **市场分组**（type: market）: A股方向、港股达人、美股视角、B股玩家、创业板关注、科创板关注（各分组人数动态，下同）
- **风格分组**（type: style）: 价值投资派、成长投资派、深度价值、逆向投资、高股息/收息、量化/技术派、困境反转、宏观视角、产业研究、消费赛道、科技赛道、资源/周期、长期持有派、趋势、波段、杠杆、分仓、集中持股、定投、左侧、右侧交易
- **状态分组**（type: status）: 完整画像

用户可以要求：
- 「给 xxx 博主加个标签 '我的核心圈'」→ 在 groups 中创建自定义分组（type: custom）
- 「把 xxx 从 '港股达人' 移除」→ 修改分组
- 「列出所有自定义分组」→ 过滤 type=custom 的分组

### 5. 多博主联合分析

当用户提出一个投资话题，希望听取多位博主意见时：

```
步骤 1: 确认参与的博主（用户指定 或 根据话题匹配分组推荐 3-5 位）
步骤 2: 依次加载每位博主的 SKILL.md，以该博主的身份和风格对话题发表观点
步骤 3: 汇总所有观点，输出联合分析报告：
  - 共识区：多数博主一致认同的观点
  - 分歧点：观点明显对立的地方（标注谁 vs 谁）
  - 独特洞察：某位博主独有的、其他博主未提及的角度
  - 风险提示：各博主提到的主要风险
```

**加权推荐算法**（当话题涉及具体股票或板块时启用）：

**话题展开**：用户输入可以是股票名或板块名。
- 输入股票名（如"腾讯"）→ 直接用 stock_mentions 计算
- 输入板块名（如"算力"、"白酒"）→ 展开为：该板块所有关联股票 + 板块关键词。对每位博主，股票分 = 该板块下所有关联股票的 stock_mentions 得分之和 + sector_mentions 中该板块的关键词提及分

registry.json 的 `sectors` 字段定义了 16 个板块，每个板块包含：
- `stocks`: 关联股票列表（用于展开查询）
- `keywords`: 板块关键词（用于 SKILL.md 文本扫描）
- `description`: 板块描述

16 个板块：AI应用、互联网平台、医药、半导体、房地产、新能源车、有色金属、消费、煤炭/能源、电信/运营商、电力/公用事业、白酒、算力/AI算力、航运/周期、银行/金融、黄金/贵金属

对每位候选博主计算综合权重分，公式：

```
权重分 = 股票提及分 × 0.50 + 资历分 × 0.30 + 影响力分 × 0.20
```

三个维度：

1. **股票提及分（50%，最高权重）**：由两部分组成：
   - **专注度分（60%）**：该股票/板块在该博主所有股票讨论中占比。占比越高说明越聚焦
   - **深度分（40%）**：维度覆盖数（持仓/预测/语录/启发式/模型），5 维 = 100 分

   板块查询时：将该板块下所有关联股票的 stock_mentions 和 sector_mentions 合并计算

   > 关键设计：使用相对专注度而非绝对提及数。一个只聊 3 只股票且其中 1 只是腾讯的博主，比聊 30 只股票其中提到腾讯的博主得分更高。

2. **资历分（30%）**：账号注册时间越长，经历过的市场周期越多，判断更有历史纵深。从雪球主页获取注册时间，计分：
   - 10 年以上：100 分
   - 5-10 年：80 分
   - 3-5 年：60 分
   - 1-3 年：40 分
   - 1 年以下：20 分
   - 未知：50 分（中间值）

3. **影响力分（20%）**：粉丝量代表市场认可度和话语权。计分：
   - 50 万+：100 分
   - 10-50 万：80 分
   - 5-10 万：60 分
   - 1-5 万：40 分
   - 1 万以下：20 分
   - 未公开：30 分

**推荐流程**：
1. 对所有 status=full 且 markets 包含该股票所在市场的博主计算权重分
2. 按权重分排序，从 Top 10 中选择 4-5 位风格差异最大的博主
3. 风格差异化判断：确保入选博主的 style_keywords 不完全重叠，优先选入不同投资流派
4. 展示推荐列表（含权重分明细）给用户确认后再开始

**输出格式**：
每位博主的发言用引用块包裹，标注「{昵称}说：」及权重分，保持该博主的表达DNA（句式、词汇、确定性风格）。

### 6. 数据更新与维护

六大更新操作，按影响范围从小到大排列：

#### 6.1 改名检测（轻量 · 不改画像）

**触发**：用户说「检查博主改名」

**流程**：
```
1. 用 autocli read 或浏览器访问每位博主的雪球主页 https://xueqiu.com/u/{id}
   （每次间隔 2-3 秒，避免触发验证码）
2. 提取主页上的最新昵称
3. 与 registry.json 中的 nickname 比对
4. 不一致时：
   a. name_change_log 追加记录 { timestamp, old_name, new_name, xueqiu_id }
   b. 更新 registry.json 的 nickname
   c. 更新 SKILL.md 中所有旧昵称位置（frontmatter、触发词、身份识别、标题）
   d. 通知用户
```

#### 6.2 粉丝数与账号信息刷新（轻量 · 不改画像）

**触发**：用户说「刷新粉丝数」或「更新博主信息」

**流程**：
```
1. 通过雪球 API 批量获取元数据：
   - 使用 browser_cookie3 解密 Chrome cookies 获取登录态
   - 访问 https://xueqiu.com/user/show.json?id={id}
   - 提取 followers_count、created_at、status_count、friends_count
   （每次间隔 2.5 秒，每 10 个一批休息 12 秒）
2. 更新 registry.json 中每位博主的：
   - followers_count（粉丝数）
   - account_age_years（注册年数，从 created_at 计算）
   - status_count（发帖总数）
3. 输出变更摘要（新增粉丝最多的 Top 5、掉粉最多的 Top 5）
```

#### 6.3 帖子增量抓取（中量 · 更新画像）

**触发**：用户说「更新 xxx 的帖子」或「增量抓取」

**流程**：
```
1. 确定目标博主（可单个或批量）
2. 从雪球主页/API 抓取 info_cutoff 之后的新帖子
   - 优先使用 autocli read 抓取帖子正文（复用 Chrome 登录态，token 低）
   - 降级方案：浏览器自动化打开 → 提取 → 关闭
3. 分析新帖子中的（原始帖子不持久化，仅保留提炼结果）：
   - 新出现的股票/标的 → 更新 stock_mentions
   - 新的投资观点/预测 → 更新 SKILL.md 的预测记录
   - 新的代表性语录 → 更新 SKILL.md 的语录段落
   - 持仓变动 → 更新核心持仓与观点
4. 更新 SKILL.md 的 post_count 和 info_cutoff
5. 更新 registry.json 对应的 post_count、info_cutoff、stock_mentions
```

**批量模式**：用户说「增量更新所有博主」时，按 info_cutoff 从旧到新排序，逐批处理。

#### 6.4 股票提及重算（轻量 · 不改画像）

**触发**：用户说「重算股票提及」或「刷新股票权重」

**流程**：
```
1. 遍历所有 xq-* SKILL.md，用预定义股票名列表（含别名）搜索五个段落：
   - 核心持仓与观点（holdings: true/false）
   - 预测记录（predictions: 计数）
   - 代表性语录（quotes: 计数）
   - 决策启发式（heuristics: 计数）
   - 核心投资模型（models: 计数）
2. 生成新的 stock_mentions 映射
3. 覆盖写入 registry.json 的 stock_mentions 字段
4. 同时扫描板块关键词：对每位博主 SKILL.md，用 sectors 中的 keywords 计数 → 写入 sector_mentions
5. 输出变更报告（股票/板块提及变化 Top 10）
```

**股票名列表**维护在 registry.json 的 `stock_aliases` 字段中（当前 46 个股票），用户可要求添加/删除别名。

#### 6.5 风格标签刷新（轻量 · 不改画像）

**触发**：用户说「刷新风格标签」

**流程**：
```
1. 遍历所有 SKILL.md 正文，用关键词列表搜索投资风格词频：
   价值投资、成长、深度价值、逆向、高股息、收息、量化、技术派、
   困境反转、长期持有、宏观、产业、消费、科技、资源、周期、
   波段、杠杆、定投、分仓、集中持股、左侧、右侧交易
2. 对每位博主，取出现频率最高的 5-7 个词作为 style_keywords
3. 更新 registry.json 的 style_keywords
4. 重建 groups 中的风格分组（type: style）
5. 输出变更（新进入/退出某分组的博主）
```

#### 6.6 全量更新（重量 · 一键全部刷新）

**触发**：用户说「全量更新雪球博主」或「refresh all」

**流程**（按顺序执行）：
```
1. 改名检测（6.1）
2. 粉丝数与账号信息刷新（6.2）
3. 帖子增量抓取（6.3）— 仅对 info_cutoff 超过 7 天的博主
4. 股票提及重算（6.4）
5. 风格标签刷新（6.5）
6. 输出完整更新报告
```

**预计耗时**：约 10-20 分钟（取决于需增量抓取的博主数量）

## registry.json 数据结构

```json
{
  "version": "1.0",
  "last_updated": "2026-06-05",
  "bloggers": [...],
  "groups": {...},
  "stock_aliases": {...},
  "sectors": {...},
  "usage_log": [...],
  "name_change_log": [...]
}
```

每位博主的 blogger 对象包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `skill_name` | string | 技能目录名（xq-{拼音昵称}） | xq-metalslime 等 |
| `xueqiu_id` | number | 雪球数字 ID |
| `nickname` | string | 当前昵称 |
| `post_count` | number | 已分析帖子数 |
| `model_count` | number | 核心投资模型数 |
| `status` | string | "full" 或 "skeleton" |
| `fan_level` | string | 粉丝量级描述 |
| `info_cutoff` | string | 信息截止日期 |
| `profile_url` | string | 雪球主页链接 |
| `markets` | array | 关注市场列表 |
| `style_keywords` | array | 投资风格关键词（5-7 个） |

## 路由效果自检

创建/修改 xq-* Skill 后，自问以下问题：

1. **会不会被误触发？** 如果用户随口提到博主名字，会不会加载？
2. **会不会抢答？** 如果用户已明确指定另一个博主，会不会跳出来？
3. **覆盖够不够？** 触发词能覆盖用户可能的表达方式吗？
4. **负样本写了没？** 「什么时候不该用」比「什么时候该用」更重要

## 诚实边界

- 分组标签基于 SKILL.md 文本分析自动生成，可能不够精准，用户可手动调整
- 改名检测依赖雪球主页可访问性，如遇反爬限制会跳过并告知
- 使用追踪只记录当前 Agent 实例内的调用，跨实例不共享
- 联合分析中的「观点」是基于博主人设的模拟，不代表博主本人当前真实看法
- 原始帖子数据不持久化，仅保留提炼后的画像到 SKILL.md；如需原始数据需重新抓取
- 路由层依赖 registry.json 的博主数据完整性，新增博主后需同步更新分组和风格标签
