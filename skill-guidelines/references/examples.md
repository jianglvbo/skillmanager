# 正反例对比

## Description

```yaml
# ❌ 错误
description: 处理投资相关的各种事情

# ✅ 正确
description: 
  雪球博主画像提炼。输入原文+控制台信息，返回完整画像。
  触发词：「博主提炼」「画像更新」。
  区别于 wiki-refine（产出投资知识而非人物画像）。
```

## Workflow 编号

```markdown
# ❌ 错误
你需要先读文件，然后检查一下字段齐不齐，缺的话就补上，最后写回去。

# ✅ 正确
1. 第一步：读取文件，校验 frontmatter
2. 第二步：缺失字段 → 报错停止；完整 → 继续
3. 第三步：生成输出，写入目标
```

## Default stance

```markdown
# ❌ 错误（缺禁止行为）
## 核心原则
- 增量更新

# ✅ 正确
## 核心原则
- 增量更新，不覆盖已有内容

## 禁止行为
- 绝不修改 pipeline 传入的路径
- 绝不删源文件
- 绝不添加原文无的观点
```

## 主文件长度

```markdown
# ❌ 错误：348 行
所有设计原则、工程规律、模板、示例全堆在主文件

# ✅ 正确：≤200 行（越短越好）
核心流程在主文件，原则→references/principles.md，规律→references/rules.md
```
