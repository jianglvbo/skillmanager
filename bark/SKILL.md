# bark

## Default stance

核心原则：
1. 一步到位：调 skill 目录下 `scripts/notify.py [标题] 正文` 即发；标题缺省「ZCode」，
   正文传 `-` 时从 stdin 读（适合多行/长文本）。
2. 通知要值得打扰：只在任务完成、失败、需要用户做决策时推送；正文一句话说清
   「发生了什么 + 下一步要用户做什么」。
3. 配置写死即约定：服务器与 device key 写死在脚本内（用户 2026-09-26 确认非敏感），
   不向用户索要，不改动，不外传给第三方服务。

禁止行为：
- 禁止无实质进展的连环推送；同一事件成功推送后不重发。
- 禁止把密钥、token、完整聊天记录等敏感内容放进正文——Bark 经公共服务器中转。
- 禁止用于给人发消息（那是 imsg 的职责）；本 skill 只推用户自己的 iPhone。

## Workflow

第一步 判定：用户显式要求通知，或长任务/高风险操作收尾需要用户知晓；否则不推送。
第二步 拟内容：标题 ≤20 字（如「任务完成」「审查发现异常」）；正文一句话，含结论
       与所需动作；不塞密钥与全文。
第三步 执行：`python3 <skill目录>/scripts/notify.py "标题" "正文"`；多行/长正文改用
       stdin（第二个参数传 `-`）。
第四步 处置结果：退出码 0 即成功，向用户一句「已推送：<标题>」；非零读输出，网络类
       错误重试一次；返回 `code:400` 设备不存在说明 key 失效，如实报告，禁止擅自改
       key 或脚本。

## Output format

- 成功：`已推送：<标题>`（一句话，不贴完整 API 返回）。
- 失败：报告退出码与 API 返回体原文，不静默。

## 自检

- [ ] 该不该推：任务收尾或用户要求才推，普通问答结论不推。
- [ ] 标题短、正文含「发生了什么 + 下一步」，无敏感内容。
- [ ] 已检查脚本退出码，失败已报告（未吞错、未擅自改配置）。
